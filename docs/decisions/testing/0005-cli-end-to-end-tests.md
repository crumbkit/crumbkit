# ADR-0005. End-to-end tests

- End-to-end tests run the built binary through snapbox's `cmd` module with a cleared environment and temporary XDG directories.
- crumbkit-test's [`check_examples`](../../../crates/crumbkit-test/src/examples.rs) runs every example of every leaf in the tool's guide against the tool's built binary, so each command line that help shows is a run that works.
- cargo gives the binary's path only to the integration tests of the binary's own package, so the check runs from one. An integration test imports only from a library, so that package has a library target that exports the clap command and the guide, and its binary calls the library, as shelf's does.
- The check runs each example with no shell, a cleared environment and fresh XDG directories, so a run depends only on what the example and the check give it. It runs the examples of hidden commands, because their own help lists them.
- `Examples::current_dir` sets the directory that each run starts in, so a tool whose examples name relative paths needs no `std::env::set_current_dir`, which changes the directory of every test in the process. The check fails without running any example when that directory does not exist. `check_twin` and `check_recoveries` run a `Failing` without its own directory in the same directory.
- `Examples::fresh_dir` names a fixture directory, and the check copies it into a new temporary directory for each run and runs there, so no example sees a file that an earlier example wrote. `check_recoveries` copies it once for each chain, so a step sees what its chain wrote, and `check_twin` copies it for each line. It and `current_dir` are one setting, and the later call wins. The check replaces the copy's path and its canonical path with `[ROOT]`, trycmd's name for its sandbox, and refuses a symbolic link as it does in an XDG fixture.
- An example reads the bytes of `<name>.stdin` in the golden directory on standard input, so the example of a command that reads standard input shows a run that works. A run without that file reads an empty standard input. The check writes the whole input before a run's 10-second limit starts, so an input file holds at most 64 KiB, the size of a common operating system pipe. The check fails on a `.stdin` file that names no example of the guide and never deletes it, because only its author can write the input again. An example that an opt-out skips keeps its input file.
- `Examples::redact` names values that change between runs, such as a temporary directory, each with a placeholder such as `[ROOT]`. The check replaces each value, matched as plain text, with its placeholder in standard output and standard error before it compares them, and `SNAPSHOTS=overwrite` writes the placeholder. The check also replaces the path of each of its own XDG directories with `[XDG_CONFIG_HOME]`, `[XDG_DATA_HOME]`, `[XDG_STATE_HOME]` or `[XDG_CACHE_HOME]`, because a test cannot know them. The check fails on a placeholder that is not `[` and `]` around capital letters and underscores, and on an empty value. The output weight read from a golden file counts the placeholder's bytes in place of the value's.
- `Examples::xdg` names a fixture directory that holds any of `config`, `data`, `state` and `cache`, and the check copies each into the fresh XDG directory of the same name before every run, so a command that needs a plugin, cache or configuration located through those variables can run without sharing state between runs. `Failing::xdg` names the fixture of one chain and wins over the fixture of `Examples`. The fresh directories keep their `[XDG_*]` placeholders. A fixture with any other entry fails the check before it runs anything, and a symbolic link in it fails the run, because a copied link could reach outside the fresh directories.
- The golden file `<name>.txt` holds the run's standard output. A run that writes to standard error also has a golden file `<name>.stderr`, which holds the notes that crumbkit prints there (ADR-0050), and a run that writes nothing there has none. `SNAPSHOTS=overwrite` writes both files and removes a `.stderr` file whose run no longer writes to standard error.
- A run that exits with a code other than 0 fails the check, because an example shows a run that works. Its problem names the failure's code and steps, read through the guide's failure form or the `FailureReader` of `Examples` when the tool has one (ADR-0045). A run whose standard error holds a line that starts with `warning: crumbkit ` also fails, because a debug build's warning marks a mistake in the tool.
- The check fails on a stale golden file, so the directory holds only example golden files, and on an opt-out from running a command's examples that names no command or skips no example, as the other tree checks do (ADR-0036). `Allow::example` opts out of one example by its words, for an example whose output no redaction can make stable, and it is stale when its command has no example with those words.
- A test of a refusal runs a twin with [`check_twin`](../../../crates/crumbkit-test/src/twins.rs): a command line that differs from the refused one by one word and succeeds. The twin shows that the changed word is the reason for the refusal, so the test cannot pass because the command fails for another reason (TEST-1). [`check_twins`](../../../crates/crumbkit-test/src/twins.rs) runs every twin of a tool and fails on a declared code that no twin refuses, unless `Twins::unprovoked` lists it with the reason no test can provoke it. A tool passes the same `Unprovoked` list to `check_recoveries`, because a code that a test can provoke can also have a twin. The check has no golden file, because every twin and every listed code is in the test's source.

Considered: snapbox's wildcards such as `[..]` in example golden files, regular expressions as redaction values, a `.stdin` file named after the example's position in its leaf, deleting a stale `.stdin` file with `SNAPSHOTS=overwrite`, an opt-out that names an example by its position, trycmd, assert_cmd, running the examples through a shell, one golden file that holds standard output and standard error together, a golden file of the exit code, a `.stderr` golden file for every example even when it is empty, failing every run that writes to standard error, the inherited environment for example runs, a tool variable that wins over its fresh XDG directory, a check that fails when both `current_dir` and `fresh_dir` are set, a fresh directory inside `current_dir`, `[CWD]` for the fresh directory, finding the binary from a unit test, including the tool's source files in the test with `#[path]`, twins that differ by any number of words.

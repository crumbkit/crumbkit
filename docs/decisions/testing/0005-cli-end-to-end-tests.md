# ADR-0005. End-to-end tests

- End-to-end tests run the built binary through snapbox's `cmd` module with a cleared environment and temporary XDG directories.
- crumbkit-test's `check_examples(command, guide, examples)` runs every example of every leaf in the tool's guide against the tool's built binary, so each command line that help shows is a run that works. `Examples` is a `const fn` builder with private fields (ADR-0002): `Examples::new(binary, dir)` takes the binary's path, from `env!("CARGO_BIN_EXE_<name>")`, and the golden directory, `.env(&[(name, value)])` adds variables to every run, such as a fixture path, and `.exempt(&[path])` skips the examples of each named command and everything below it.
- cargo sets `CARGO_BIN_EXE_<name>` only for the integration tests of the binary's own package, so the check runs from one. An integration test imports only from a library, so that package has a library target that exports the clap command and the guide, and its binary calls the library, as shelf's does. cargo runs those tests, and the binary, from the package's manifest directory, where relative paths in `dir` and `.env` resolve.
- The check runs the examples one at a time, in the guide's order, with the leaf's path and the example's words as separate arguments and no shell. Each run has a cleared environment, the `.env` variables, and `XDG_CONFIG_HOME`, `XDG_DATA_HOME`, `XDG_STATE_HOME` and `XDG_CACHE_HOME` pointing at fresh directories that the check creates and deletes. It skips a leaf whose path names no command, which `check_guide` reports, and runs the examples of hidden commands, because their own help lists them.
- The golden file holds the run's standard output only. A run that exits with a code other than 0 or writes to standard error fails the check with its command line, exit status and standard error, because an example shows a run that works, and with `SNAPSHOTS=overwrite` its file is not written. A binary that cannot start fails with its path and the error.
- A golden file's name joins the tool's name, the leaf's path and the example's words with dashes, such as `shelf-books-list-all.txt`. In each part, every run of characters other than ASCII letters, digits, `.` and `_` becomes one dash, a leading or trailing dash is dropped, and an empty part is left out. Two examples with one name fail the check, naming both command lines.
- Without `SNAPSHOTS=overwrite`, the check fails on a missing file, a file whose content differs and a stale file, which is a `.txt` file in `dir` that no checked example produces, such as the file of an exempt example, and `dir` holds only example golden files. With `SNAPSHOTS=overwrite`, it writes and rewrites the files and deletes each stale one. An exemption that names no command fails the check, as in the other tree checks (ADR-0015).

Considered: trycmd, assert_cmd, running the examples through a shell, golden files that also hold standard error and the exit code, the inherited environment for example runs, finding the binary from a unit test, including the tool's source files in the test with `#[path]`.

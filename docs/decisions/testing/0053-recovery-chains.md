# ADR-0053. Recovery chains

- crumbkit-test's [`check_recoveries`](../../../crates/crumbkit-test/src/recoveries.rs) runs command lines that fail, which the tool's test lists with the code each fails with, and follows each `run` recovery and alternative that the failures print, up to 3 steps by default. A step that the parser refuses or that fails again with the same code fails the check, because an agent that follows the recovery would be stuck. Every declared code is provoked by a chain or listed with the reason no test can provoke it. The check pins the chains, codes and outcomes in the golden file `recoveries.txt`, without messages, so a changed recovery shows in review.
- The runs of one chain share fresh XDG directories, so a step sees what the earlier runs wrote, such as a confirmation that a remove needs. A placeholder such as `<ID>...` or `<path>` takes the first value of three sources: the chain's own `Failing::values`, then a field of the failure that offers the step, then the shared `Recoveries::values`, so each chain can fill `<path>` with the path its own failure named. Each placeholder that a field fills is a finding of `Rule::FieldValue`, id `recoveries/field-value`, and the report shows it under the step, because an agent that follows the recovery must copy the value itself, while a recovery built with `Call::value` carries it. A tool that cannot carry the value opts out with an `Allow` that names the command whose failure printed the recovery. A start's own value that wins over a field is no finding. A table value matches the name exactly, case included, because a tool may write its placeholders in either case. A field matches with capitals lowered and `-` read as `_`, because field names are always lowercase and clap writes its placeholders in capitals. The fields come with the failure that the check reads: those that the tool's form or reader returns in its `ReadFailure`, or the `fields` of crumbkit's failure document, so the code, steps and fields always belong to one failure. A placeholder can sit anywhere in a word, so `<plugin>.<capability>` fills two placeholders and keeps the `.`, and a `<` that starts no placeholder stays literal text. The check reads a step's words with its own `split`, which reads single and double quotes as a POSIX shell does and refuses a `$` or a backtick between double quotes, so a tool need not re-quote its hints with `help::quote`. `split` is private to crumbkit-test, because only the check reads a recovery's words, and crumbkit offers only `help::quote`. A code that the tool does not declare and crumbkit does not own ends its chain, and the report counts such codes.
- `check_recoveries` runs each start and step in the working directory, standard input and XDG fixture that ADR-0005 describes for examples and twins.

Considered: a field fill reported only in the golden file, an opt-out that names the step's command, a finding for a `Failing::values` entry that wins over a field, setup command lines that run before a start, a setup function that receives the XDG paths, shared values that win over a failure's fields, fields that match a placeholder's case exactly, a second read of the document's fields beside the failure, placeholders joined only by fixed separators, following recoveries from the failures that the examples provoke, generating failing command lines from the clap tree, a recovery check without a golden report.

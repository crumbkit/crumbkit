# ADR-0012. Supply chain and releases

- cargo-deny's licence, ban and source checks and cargo-shear enforce CI-2 in the pull-request `lint` job, because they take seconds and stop a bad dependency before it merges. CI-2 holds because an unexpected licence binds adopters, an unknown source can serve code that nobody reviewed, and an unused dependency adds build time for nothing. `deny.toml` allows only the licences the graph uses and only crates.io as a source, and it bans duplicate versions, wildcard version requirements, the async runtimes and C build tools that ADR-0003 rules out, and clap in any crate that its list of clap users leaves out, which keeps clap out of crumbkit-core (ADR-0032). It also fails on an executable or a script inside a crate that runs at compile time, except the helper scripts that `deny.toml` names with the reason no build runs them.
- cargo-deny's advisories check runs in the nightly lane of ADR-0011, because a new advisory can appear when no code has changed.
- Dependabot checks the cargo and GitHub Actions dependencies weekly and puts each ecosystem's version updates in one pull request. It proposes a release only after a 7-day cooldown, so the ecosystem has time to find and yank a compromised release.
- The four published crates, crumbkit-core, crumbkit, crumbkit-test and crumbkit-aliases, share one version and one root `CHANGELOG.md`, and each release will have one tag for all four. crumbkit-core and crumbkit release together at that version, because crumbkit re-exports crumbkit-core's items (ADR-0032). release-plz will publish them through crates.io trusted publishing once a release workflow exists, and nothing is published yet.

Considered: cargo-audit, cargo-udeps, cargo-machete, advisories on every pull request, one pull request per update, Renovate, cargo-release.

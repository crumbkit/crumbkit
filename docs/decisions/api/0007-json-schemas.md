# ADR-0007. JSON schemas

- Every JSON document is an object with a `schema` id and the result under `data`, such as `{"schema":"shelf/books-list/v1","data":[...]}`.
- A listing's document also holds the number of matching rows under `total`, after `data`, such as `{"schema":"shelf/books-list/v1","data":[...],"total":6}`. `total` is present with every output flag, including `--full` and `--fields`, so a program can tell whether it has every row.
- A batch's document also holds the failures for the ids that did not work under `failures`, after `data`, such as `{"schema":"shelf/books-show/v1","data":[...],"failures":[...]}`. `failures` is present for every batch and is empty when every id worked, as `total` is present for every listing. Each entry has exactly the fields of the `crumbkit/failure/v1` document except `schema`, and crumbkit writes both from the same code, so the two shapes cannot drift.
- A document id is `component/name/vN`. A tool declares it as a typed constant, such as `const BOOKS_LIST: Document<Vec<Book>> = Document::new("shelf", "books-list", 1)`, so the compiler ties the id to its result type. `Document::new` is a `const fn` that fails compilation unless the component is non-empty lowercase ASCII letters, digits and underscores, the name is non-empty lowercase ASCII letters, digits and dashes, and the version is at least 1.
- Every JSON document type has a 2020-12 `JsonSchema`. A test compares each schema with its checked-in file, which the binary serves. crumbkit implements the failure document's schema by hand and checks it in as `crates/crumbkit/schemas/failure-v1.json`, checks in the schema of the `crumbkit/commands/v1` document of `commands list` as `crates/crumbkit/schemas/commands-v1.json` (ADR-0026), and checks in `crumbkit/aliases/v1` as `crates/crumbkit-aliases/schemas/aliases-v1.json` (ADR-0027).
- With the `miette` feature, the failure document also has `labels` after `cause` when the failure's diagnostic has at least one label, and so does each entry of a batch's `failures`. Each label is an object with the span's byte `offset` and `length`, the source's `name` when it has one, the 1-based `line` and `column` when the span could be read, where the column counts characters, and the label's `text` when it has one; the source line stays out of the JSON. The checked-in schema lists `labels` whether or not the feature is on, so there is one schema file, and the optional field keeps the `v1` id because readers ignore unknown fields.
- Removing, renaming or retyping a field, making it optional, or adding an enum value needs a new `/vN` id. Readers ignore unknown fields.
- A `Recovery` is tagged by `kind`: `run` with `call`, `retry`, `hint` with `text`, or `none` with `reason`.
- The failure document `crumbkit/failure/v1` has `schema`, `code` in the tool's spelling, `message` (the failure's `Display`), `cause` only when the failure has a source, `recovery`, and `url` when present. `cause` is one string, the `Display` of each error in the source chain joined with `: `, because those errors usually come from libraries whose wording and depth are not stable, so a program matches on `code` and shows `cause` as one line. The schema allows any `code` of one or more printable ASCII characters (`!` to `~`), because each tool chooses its own spelling.

Considered: hand-written schemas, `cause` as an array of strings, boon, an untyped string id, a `total` only when rows were left out, a `next` field holding the same command with `--all`, `failures` only when an id failed, a `schema` in each entry of `failures`.

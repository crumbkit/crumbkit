# ADR-0007. JSON schemas

- Every JSON document is an object with a `schema` id and the result under `data` ([`finish`](../../../crates/crumbkit/src/output.rs)).
- A listing's document always holds `total`, with every output flag, so a program can tell whether it has every row ([`Listing`](../../../crates/crumbkit-core/src/listing.rs)).
- A batch's document always holds `failures`, which is empty when every id worked, as `total` is present for every listing ([`Batch`](../../../crates/crumbkit-core/src/batch.rs)). Each entry has the fields of the failure document except `schema`, and crumbkit writes both from the same code, so the two shapes cannot drift.
- A document id is a typed constant, a [`Document`](../../../crates/crumbkit-core/src/document.rs), so the compiler ties the id to its result type and rejects a malformed id. It holds a one-line description, which becomes the schema's `description`.
- The name of the document that a command prints is the command's path below the tool joined with `-`, such as `shelf/books-list/v1` for `shelf books list`, so an agent can predict a document's id from the command it ran, and the command from an id. crumbkit-test's `check_document_ids` enforces the rule, and ADR-0035 records its cases.
- Every JSON document type has a 2020-12 `JsonSchema`, and `schemas::document_schema` builds the schema of a whole document from its id and its result type. A test compares each of crumbkit's schemas with its checked-in file in a `schemas` directory, and a tool serves the schemas of the documents it prints through `schemas list` and `schemas show` and pins them with `check_schema_goldens` (ADR-0035). The usage record is one line of a log, so it has its fields at the top level beside `schema`, without `data` (ADR-0029).
- With the `miette` feature, the failure document and each batch failure hold the diagnostic's labels, and the source line stays out of the JSON. The checked-in schema lists `labels` whether or not the feature is on, so there is one schema file, and the optional field keeps the `v1` id because readers ignore unknown fields.
- Removing, renaming or retyping a field, making it optional, or adding an enum value needs a new `/vN` id. Readers ignore unknown fields.
- A failure's `cause` is one string that joins the source chain, because those errors usually come from libraries whose wording and depth are not stable, so a program matches on `code` and shows `cause` as one line. The schema accepts any spelling of `code`, because each tool chooses its own spelling (ADR-0001).

Considered: hand-written schemas, a hand-written envelope type per document, document names chosen freely, `cause` as an array of strings, boon, an untyped string id, a `total` only when rows were left out, a `next` field holding the same command with `--all`, `failures` only when an id failed, a `schema` in each entry of `failures`.

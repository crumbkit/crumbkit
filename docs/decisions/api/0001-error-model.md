# ADR-0001. Errors

- A tool's error types implement [`Failure`](../../../crates/crumbkit-core/src/failure.rs) beside `std::error::Error`, which adds a stable code, a recovery and an optional url. The failure's `Display` and its `source()` chain give the message and the causes, and Debug formatting never reaches the output.
- Every failure states a [`Recovery`](../../../crates/crumbkit-core/src/failure.rs). A `Run` call that the tool's command tree cannot render prints as `None` with crumbkit's reason, so crumbkit never advertises a command the tool hid.
- A `Run` call can carry concrete values with `Call::value`, so a failure can suggest the exact command that repairs it. Rendering refuses a value that the tool would refuse before it runs: a value for a flag, a value outside the argument's possible values, and a positional value that clap would read as a flag.
- A command line that clap refuses and an unknown `--fields` name fail with one fixed crumbkit code ([`parse`](../../../crates/crumbkit/src/parse.rs), [`Output`](../../../crates/crumbkit/src/output.rs)). The recovery of a refused command line runs the `-h` of the deepest command the caller typed, even a hidden one, because the caller typed its name.
- A [`Code`](../../../crates/crumbkit-core/src/code.rs) has three segments, the owning component, the area and the reason, and `Code::new` checks them at compile time. Each error type lists its codes in a `CODES` list for crumbkit-test's `check_codes`, and nothing registers codes at runtime.
- Each tool chooses how its codes are spelled with one [`Spelling`](../../../crates/crumbkit-core/src/code.rs), and passes the same spelling to `finish` and to `check_codes`. `Code` has no `Display`, so every printed code goes through the tool's spelling. A code is an identifier that callers match exactly, so `check_codes` refuses characters that let two different codes look the same.
- The optional `miette` feature lets a failure that implements `miette::Diagnostic` show its labels, and crumbkit draws them itself (ADR-0016, ADR-0007). The code, the recovery and the url still come from `Failure`.
- With the `miette` feature, a `miette::Report` converts into `Error` with one fixed code ([`report`](../../../crates/crumbkit-core/src/report.rs)), so `?` works on a `miette::Result`. The fixed code tells the caller only that the failure was not classified, so a tool that wants its own failure back calls `report.downcast` before converting.
- [`Error`](../../../crates/crumbkit-core/src/failure.rs) holds any failure, so `?` works across a tool's error types. It has no context methods. It cannot implement `Failure`, because its blanket `From` would overlap with the standard library's `From<T> for T`, so `finish` accepts a `Failure` or an `Error` through the sealed `AsFailure` trait.
- A later `crumbkit-derive` uses its own `#[failure(code = ..., recovery = ...)]` attribute. It waits until hand-written `impl Failure` blocks prove a burden.

Considered: literal words appended to a call without a check against the tree, the `Display` as the cause line, a required miette dependency, a blanket impl over `miette::Diagnostic`, converting failures into `miette::Report`, reading miette's `#[diagnostic]` attribute, error-stack, a separate `help()` method beside `Hint`, registering codes on an `App` value, context wrapping on `crumbkit::Error`, one fixed `::` spelling for every tool, a global spelling set once at startup, accepting only declared codes from a `miette::Report`, miette's graphical renderer, miette's narratable renderer, printing a report's own code through a second failure path, an adopter-supplied finder, a usage code that the tool passes in, a usage code built from the command's name, a `--fields` recovery that runs the root's `-h`.

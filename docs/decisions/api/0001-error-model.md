# ADR-0001. Errors

- `Failure: std::error::Error` has `code() -> &'static Code` and `recovery() -> Recovery`, plus a provided `url()` that returns `None` by default. The failure's `Display` is the `error:` line, and each error in its `source()` chain prints as one `cause:` line, in order, so a failure with no source has no `cause:` line. Debug formatting never reaches the output.
- `Recovery` has the variants `Run(Call)`, `Retry`, `Hint(text)` and `None { reason }`, and every failure states one. Text output prints it on the `help:` line.
- `finish` renders a `Run` call against the command from `Output::set_command`. When no command is set or the call does not resolve, the failure prints as `None` with crumbkit's reason `the suggested command is not available`, in text and JSON, so crumbkit never advertises a command the tool hid and the failure still states a recovery.
- A code has three segments: the owning component, the area and the reason, each of lowercase letters, digits and underscores. `Code::new` is a `const fn` that rejects a bad segment at compile time. Each error type exposes its codes in a `CODES` list, which crumbkit-test's codes check receives, and nothing registers codes at runtime.
- Each tool chooses how its codes are spelled with one `Spelling`, a function from a `Code` to text: `Spelling::COLONS` (`shelf::books::not_found`), `DOTS`, `SLASHES`, or any function given to `Spelling::custom`. The binary passes its spelling to `finish`, and its test passes the same spelling to the codes check, which fails on two codes that spell the same, an empty code, or a code with a character other than printable ASCII (`!` to `~`). A code is an identifier that callers match exactly, and a space, a control character or a character outside ASCII lets two codes look the same while they differ. `Code` has no `Display`, so every printed code goes through the tool's spelling.
- The optional `miette` feature, off by default, adds a provided `Failure::diagnostic()` that returns `None`. A failure type that also implements `miette::Diagnostic` returns `Some(self)`, and crumbkit reads only the diagnostic's labels and source code, so the code, recovery and url still come from `Failure`. crumbkit draws each label itself from miette's `SourceCode::read_span`, as an `at:` line with the source line and a caret underline in text (ADR-0016) and as an entry of `labels` in JSON (ADR-0007).
- With the `miette` feature, `Error` also converts from a `miette::Report`, so `?` works on a `miette::Result`. The failure's code is always `crumbkit::report::unchecked` in the tool's spelling, its message is the report's `Display` followed by the report's own code in parentheses when it has one, its recovery is the report's help as a `Hint` or else `None` with a reason, its url is the report's url, and its labels print as a diagnostic's do. The fixed code tells the caller only that the failure was not classified, so a tool that wants its own failure back calls `report.downcast` before converting.
- `crumbkit::Error` wraps a `Box<dyn Failure + Send + Sync>` and converts from every `Failure`, so `?` works across a tool's error types. It has no context methods. It cannot implement `Failure`, because the blanket `From` would then overlap with the standard library's `From<T> for T`, so `finish` accepts a `Failure` or an `Error` through the sealed `AsFailure` trait. `Error` implements `std::error::Error` with the `Display` and `source()` of the failure inside, so a tool's `main` can pass it on to `Box<dyn std::error::Error>` or another error library.
- A later `crumbkit-derive` uses its own `#[failure(code = ..., recovery = ...)]` attribute. It waits until hand-written `impl Failure` blocks prove a burden.

Considered: the `Display` as the cause line, a required miette dependency, a blanket impl over `miette::Diagnostic`, converting failures into `miette::Report`, reading miette's `#[diagnostic]` attribute, error-stack, a separate `help()` method beside `Hint`, registering codes on an `App` value, context wrapping on `crumbkit::Error`, one fixed `::` spelling for every tool, a global spelling set once at startup, accepting only declared codes from a `miette::Report`, miette's graphical renderer, miette's narratable renderer, printing a report's own code through a second failure path, an adopter-supplied finder.

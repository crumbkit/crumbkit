# ADR-0001. Errors

- `Failure: std::error::Error` has `code() -> &'static Code` and `recovery() -> Recovery`, plus a provided `url()` that returns `None` by default. The cause line is the error's `Display`.
- `Recovery` has the variants `Run(Call)`, `Retry`, `Hint(text)` and `None { reason }`. Text output labels the hint line `help:`.
- A code has three segments: the owning component, the area and the reason, each of lowercase letters, digits and underscores. `Code::new` is a `const fn` that rejects a bad segment at compile time. Each error type exposes its codes in a `CODES` list, which crumbkit-test's codes check receives, and nothing registers codes at runtime.
- Each tool chooses how its codes are spelled with one `Spelling`, a function from a `Code` to text: `Spelling::COLONS` (`shelf::books::not_found`, the default), `DOTS`, `SLASHES`, or any function given to `Spelling::custom`. The binary passes its spelling to `finish`, and its test passes the same spelling to the codes check, which fails on two codes that spell the same, an empty code, or a code with whitespace or characters outside ASCII. `Code` has no `Display`, so every printed code goes through the tool's spelling.
- The optional `miette` feature, off by default, adds a provided `Failure::diagnostic()` that returns `None`. A failure that returns `Some(self)` gets miette's source snippet, labels and cause chain in its text output, and its code, recovery and url still come from `Failure`. Without the feature, an error that points into a file prints no snippet. CI builds and tests with and without the feature.
- The `miette` feature also renders a `miette::Report`. It prints the report's code unchanged when the code is non-empty ASCII without whitespace, maps its help to `Recovery::Hint` and its labels to `labels`, and an optional adopter-supplied finder recovers the adopter's own `Failure` from the report's chain. Any other code is replaced by the code with segments `<component>`, `cli` and `unchecked` in the tool's spelling, with the original string in the message.
- `crumbkit::Error` wraps a `Box<dyn Failure + Send + Sync>` and converts from every `Failure`, so `?` works across a tool's error types. It has no context methods.
- A later `crumbkit-derive` uses its own `#[failure(code = ..., recovery = ...)]` attribute. It waits until hand-written `impl Failure` blocks prove a burden.

Considered: a required miette dependency, a blanket impl over `miette::Diagnostic`, converting failures into `miette::Report`, reading miette's `#[diagnostic]` attribute, error-stack, a separate `help()` method beside `Hint`, registering codes on an `App` value, context wrapping on `crumbkit::Error`, one fixed `::` spelling for every tool, a global spelling set once at startup, accepting only declared codes from a `miette::Report`.

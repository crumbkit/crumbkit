# ADR-0032. The clap-free core crate

- [crumbkit-core](../../../crates/crumbkit-core/README.md) holds the types that need no clap, so a crate that is not a command-line tool, such as a web server that maps a `Failure` to an RFC 9457 problem-details response, builds without clap. crumbkit depends on crumbkit-core and re-exports each of its items at the path the item had in crumbkit, so a tool built on crumbkit keeps its code.
- An item belongs in crumbkit-core when it compiles without clap and a caller that is not a command-line tool would use it. By that rule crumbkit-core holds `Code` and `Spelling`, `Failure`, `Recovery`, `Error` and `AsFailure`, `Document`, `Call` and `CallError`, `Row`, `Rows`, `Shape` and `NoRow`, `Listing`, `Batch` and `Prose`. crumbkit keeps parsing, help, `Output`, `Page`, `finish`, the failure document, refusals, `commands list`, `fetch_each`, the exit-code helper, the run observer, the usage log and the trace context, because each is either built on clap or serves only a process run from a command line.
- `Rows::SHAPE` names a result's kind, so crumbkit's `schemas::document_schema` builds the fields of a document from its result type, and `Document::untyped` returns the same id as a `Document<()>`, so a `Leaf` keeps a document without its type (ADR-0035).
- `Call` holds names, the concrete values that `Call::value` adds and the argument that `Call::all` fills with every value of a list field of the failure, and crumbkit's sealed `RenderCall` trait gives it the `render` method that reads a `clap::Command`. `Call::help` and `Call::target` are public, because crumbkit builds and renders calls from outside crumbkit-core.
- crumbkit-core depends on serde_json, because `Batch::has_room` measures each row as the compact JSON that crumbkit prints. `FieldValue::from_json` reads a failure field back from a `serde_json::Value` in crumbkit-core, beside `FieldValue`, so a test or a tool that reads failure fields from JSON does not copy the conversion. It puts serde_json's major version into crumbkit-core's API, which couples nothing new, because crumbkit's `FailureForm::json` already returns a `serde_json::Value`.
- crumbkit-core's `miette` feature adds `Failure::diagnostic` and the conversion of a `miette::Report` into `Error`, and crumbkit's `miette` feature turns it on.
- crumbkit-core's `derive` feature re-exports `#[derive(Failure)]` from crumbkit-derive beside the trait of the same name, and crumbkit's `derive` feature turns it on, so `crumbkit::Failure` names both. A procedural macro must live in its own crate, and the derive writes paths under `::crumbkit` unless its `crate` key names `::crumbkit_core` (ADR-0001).
- crumbkit-core holds `Error::unclassified` and its code, `codes::REPORT_UNCHECKED`, because neither needs clap and a crate that is not a command-line tool also meets errors that it does not classify. crumbkit re-exports the code in its own `codes` module.
- `deny.toml` bans clap and clap_builder for every crate except the ones it lists as direct users, so `cargo deny check bans` fails when clap enters crumbkit-core's dependency tree.

Considered: clap behind an optional default feature of crumbkit, which needs cfg attributes across many modules and an extra CI build without the feature, and would not stop clap-free code from starting to use clap; `render` as a free function; the failure document in crumbkit-core; `fetch_each` in crumbkit-core; `Call::help` hidden from the docs, `Call::word` for runtime words that skip the check against the tree, `TryFrom<&serde_json::Value>` for `FieldValue` with an error type, a fraction read as its JSON text, the conversion in crumbkit or crumbkit-test.

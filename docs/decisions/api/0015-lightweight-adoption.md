# ADR-0015. Lightweight adoption

- crumbkit is light to adopt in concepts and in dependencies. A tool keeps its own clap derive types and its own `main`, and each part works on its own, so a tool adopts only the parts it wants. The default build depends on few crates, which `Cargo.toml` lists with a reason for each (ADR-0003). It enables clap's `help` feature, so a tool built with crumbkit always has `-h` and `--help`.
- Each part follows an existing convention: `Failure` extends `std::error::Error`, `Output` is added with clap's `#[command(flatten)]`, results derive `Serialize` and `JsonSchema` and implement `Row` to name their table columns, and each crumbkit-test check is a free function that a tool calls from an ordinary `#[test]`, as it calls clap's `Command::debug_assert`.
- The optional `crumbkit::run` one-liner arrives in a later release as a thin layer over the public parts. It adds no concept, does nothing a hand-wired `main` cannot, and no part requires it.
- A tool's `main` parses with [`parse`](../../../crates/crumbkit/src/parse.rs) in place of clap's `Cli::parse`. `parse` returns the exit code instead of calling `process::exit`, so every invocation ends by returning from `main`, and tests run in memory through `parse_to`.
- Help pages and the `Call`s in `Next:` lines and recoveries are rendered from the `clap::Command` a tool builds at runtime, which may hide or remove commands, and so will MCP tool lists, which arrive in a later release. A tool's `main` passes the command that `parse` returned to `Output::set_command` itself, once. A `Call` that does not resolve against that command is left out or printed as `Recovery::None` (ADR-0001), so crumbkit never prints a command the tool hid.
- A command sets its own output defaults on its arguments type, such as the default limit of the `Page` it flattens. `parse` takes no defaults for a branch. A separate function that runs before parsing will set them by command path, with the nearest entry winning, and it arrives in a later release.
- A command that refuses the caller returns an ordinary `Failure`. crumbkit-test and the golden files check the full tree.
- crumbkit-test checks a command tree with free functions that each take a `clap::Command` and their settings as plain arguments, and report every problem at once with the path of each command. The rustdoc of each check lists what it fails on.
- [`check_names`](../../../crates/crumbkit-test/src/names.rs) fails on every second name that help shows. Help is what agents read and copy, so each visible alias costs help tokens and teaches a second spelling, while a hidden alias costs neither and lets a retired name keep working for a while or a common wrong guess parse. crumbkit's `Next:` lines and recoveries always print the real name, and a refusal replaces each flag or subcommand that clap suggests by a hidden alias with the real name it belongs to.
- [`check_grammar`](../../../crates/crumbkit-test/src/grammar.rs) requires the form `<tool> <resource> <verb>`. It reserves `--dry-run` for the write verbs that come after 0.1, and `help` for asking for help (ADR-0023). It checks only a name's form, so review checks that each resource is plural.
- [`check_listings`](../../../crates/crumbkit-test/src/listings.rs) requires `Page`'s flags on every `list` command and a positional argument that takes many ids on every `show` command. [`check_filters`](../../../crates/crumbkit-test/src/filters.rs) requires an option that accepts many values to accept both repeats and commas and to take one value per use, because an option that takes several values per use swallows the positional words after it. Review checks that an option that takes one value refuses a second, because clap has no documented getter for `Command::args_override_self` or for an `Arg::overrides_with` that names the argument itself, and a getter in a later clap release would let `check_filters` cover the rule.
- `check_guide` takes no exemptions, because a tool that wants clap's list for a command leaves that command out of its guide (ADR-0021), and neither do the help checks (ADR-0025). Each other tree check takes a list of exempt command paths and fails on an exemption that names no command, so the exemption of a removed command cannot stay. The tree checks walk the tree as the tool built it, without `Command::build`, so they never see clap's generated `help` subcommand or its `--help` and `--version` flags.
- Every function that takes a `clap::Command` works on any node of the tree, so a crate or a team can apply crumbkit and crumbkit-test to its own subtree. A tool adds `commands list` at the root, because it lists branches of the tree that `main` passes to `Output::set_command` (ADR-0026). A tool with personal aliases passes its arguments through `crumbkit_aliases::expand` before `parse_from` (ADR-0027).
- A tool that keeps the usage log turns on crumbkit's `usage-log` feature and calls `crumbkit::usage::start()` first in `main`, and changes nothing else (ADR-0029). The trace context and the `tracing` feature need no wiring beyond that and a subscriber the tool installs (ADR-0030).
- The first segment of a code names the component that owns the code, so a crate keeps its codes in whatever binary includes it. In a tool built from one crate, the component and the tool have the same name.
- `show` accepts many ids and returns a `Batch` (ADR-0016). [`fetch_each`](../../../crates/crumbkit/src/fetch.rs) runs a per-id lookup on a bounded number of scoped threads for a tool whose backend has no batch lookup. crumbkit has no default worker count, so each tool chooses one. An async tool uses its own bounded stream, because `fetch_each` blocks the calling thread, and a tool that needs rate limits or retries writes its own loop.

Considered: an `App` runner that owns dispatch, a required derive macro, rendering from the compile-time tree, a trait with a provided `show_many`, an async runtime for concurrent lookups, a default worker count for `fetch_each`, builder-style tree checks, one grammar check with per-rule exemptions, no short flags, only `-h` and `-V` as short flags, a fixed verb list with exemptions, a plural check, a hidden getter for `args_override_self`, a parse probe with the option given twice, no aliases at all, hidden ones included, a trait that finds `Output` inside the tool's type, `parse` taking `&mut Command`, `parse` returning `Output` beside the tool's type, `process::exit` inside `parse`.

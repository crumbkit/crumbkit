# ADR-0035. Schema commands

- `<tool> schemas list` lists the JSON documents that a tool prints, and `<tool> schemas show <ID>...` prints the JSON Schema of each, so an agent learns the shape of a document from the tool it runs ([`schemas`](../../../crates/crumbkit/src/schemas.rs)). The tool adds a `schemas` group whose `list` and `show` subcommands take `SchemasList` and `SchemasShow`, and its handlers pass `schemas::list` and `schemas::show` to `finish` with `SCHEMAS_LIST` and `SCHEMAS_SHOW`. shelf shows the wiring.
- The tool's `Guide` is the source of the documents. Each leaf that declares its document with `Leaf::document` adds that document, and crumbkit adds `crumbkit/failure/v1` first, because every command prints it when it fails with `--json`. A leaf whose path is hidden in the command tree that `main` passed to `Output::set_command` adds nothing, so the commands list only what help shows (ADR-0015). Two leaves that declare one id give one row that names both command lines.
- `Document::new` takes a one-line description, which `schemas list` prints beside each id and which becomes the schema's `description`. A required argument means every document has one, and the compiler finds a document without one.
- `schemas::document_schema` builds the whole JSON Schema of a document from its id and its result type: the `schema` constant, `data`, and `total`, `summary` or `failures` by the result's shape (ADR-0007, ADR-0016). `schemas show` and the tests of the checked-in schema files call the same function, so the served schema and the checked-in file cannot drift. A batch's `failures` entries use the failure document's schema without its `schema` property.
- `schemas show` takes 1 to 100 ids, as every `show` command does, and returns a `Batch` (ADR-0016). An id that names no document adds a failure with the code `crumbkit::schemas::not_found`, whose recovery runs `schemas list`. Text output prints each schema as compact JSON in one table cell, so a caller who wants it pretty-printed uses `--json`.
- Both commands fail with `crumbkit::schemas::unavailable` and no next step when the tool's `main` has not passed its command to `Output::set_command`, because without the tree they cannot tell which commands are visible. crumbkit fixes both codes, as it fixes those of `commands list` (ADR-0026).
- The name of the document that a leaf prints is the leaf's path below the tool joined with `-`, so `shelf books list` prints `shelf/books-list/v1` and `schemas list` prints `crumbkit/schemas-list/v1`. An agent can then predict a document's id from the command it ran, and the command from an id. A cargo subcommand's path starts below its own name, so `cargo crumbkit weigh` prints `crumbkit/weigh/v1`. The failure document and the usage record are printed by no single command, so their names are `failure` and `usage`. crumbkit-test's [`check_document_ids`](../../../crates/crumbkit-test/src/documents.rs) fails on a leaf whose document breaks the rule and names the expected name. It checks only the name, because a tool chooses the component and `Document::new` checks the form of each part.
- crumbkit's own commands sit at fixed paths below the tool: `commands list`, `schemas list`, `schemas show`, `self usage`, `self figures list` and `aliases list`. An agent that knows one crumbkit tool then runs them in every other by the same words. crumbkit-test's [`check_mounts`](../../../crates/crumbkit-test/src/documents.rs) fails on a leaf that declares one of their documents at another path and names the path it belongs at. A command tree does not record the Rust type of a command's arguments, so the check knows crumbkit's commands by the document their leaf declares, and review checks a command that takes crumbkit's arguments type without such a leaf. The id check skips these documents, so each failure names one fix.
- crumbkit-test's [`check_schema_goldens`](../../../crates/crumbkit-test/src/schemas.rs) compares the schema of each document that `schemas show` serves with a golden file named after its id, such as `shelf-books-list-v1.json`, so a change to a document's shape shows in review, where ADR-0007 decides whether it needs a new version. It skips the documents of the component `crumbkit`, whose schemas crumbkit's own tests pin. It also fails on two leaves that declare one id with different schemas, because `schemas show` serves only the first.

Considered: a `Schemas` trait that each result type implements, a registry of documents separate from the guide, an optional description, the schema pretty-printed in text output, a single-id `schemas show`, schema goldens for crumbkit's documents in every tool, free document names, the id check and the mount check as one check, finding crumbkit's commands by their arguments type.

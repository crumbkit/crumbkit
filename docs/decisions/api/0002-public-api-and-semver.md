# ADR-0002. Public API and semver

- Each release pull request that release-plz opens runs cargo-semver-checks against the last published version, so the checks start at 0.1.1, and its review goes through the Rust API Guidelines checklist (ADR-0012).
- crumbkit re-exports every public item of crumbkit-core at the path the item had in crumbkit, so crumbkit-core's public API is part of crumbkit's (ADR-0032). `Call::help` and `Call::target` are public and documented like every other item, because crumbkit builds and renders calls from outside crumbkit-core.
- Configuration types have private fields and `const fn` builders. A type that holds data read at run time, such as `RuntimeLeaf` or crumbkit-test's `RuntimeFailing`, has ordinary builders where a `const fn` cannot add to a `Vec` or replace an owned value, and leaks into the `'static` type that the `const` builders make. `RuntimeFailing::at` makes a `RuntimePlace`, a separate type without a code, from which `RuntimePlace::line` builds each command line, so a place passed where a command line belongs is a compile error. The two types share one private settings struct, and `RuntimePlace` repeats each settings builder as a one-line method, which costs about 70 lines and keeps every call that built a place before compiling. A settings type whose `const` constructor borrows a tool's codes, such as `Twins`, `Recoveries` and `Unprovoked`, has a second `const` constructor that takes codes held by value, because a `const fn` cannot take a generic argument that converts. Enums that may grow are `#[non_exhaustive]`, and adopter-implemented traits gain only methods with defaults.
- Handlers take an arguments struct deriving `clap::Args`, `Serialize` and `JsonSchema`, and never see `ArgMatches`.
- Failure codes are never reused. A run exits with 0 when it succeeds. By default a failure exits with 1 and a refused command line with 2, and a tool may give any failure, crumbkit's included, its own code from 3 to 125 by listing the failure's code in an `Exit` of its guide, so `finish`, a stream and a refusal end with that code (ADR-0037, ADR-0056). A shell reports 126 and above for its own reasons, such as 130 when SIGINT ends the process and 143 when SIGTERM does, and the usage log's signal handling leaves those codes in place. A command that hands the terminal to a child returns the child's exit code, so on that command 1 and 2 carry the child's meanings (ADR-0042). ADR-0037 records how a tool declares its codes.
- `parse` returns a [`Stop`](../../../crates/crumbkit/src/parse/stop.rs) in place of a bare `ExitCode` when it ends the run, so a tool can still ask whether the caller wanted JSON. Its `Output` sits in a `Box`, because `Output` holds a whole `clap::Command` and clippy's `result_large_err` flags a large error type, and the box costs one allocation only on a run that `parse` ends.
- `parse` returns a `Parsed` that keeps the caller's words for `Output::confirm` (ADR-0039), with any values that a picker added (ADR-0043), and whether the caller passed `--no-input`. The `Picker` trait is implemented by adopters, so it gains only methods with defaults, and `Answer` is `#[non_exhaustive]`.
- The `complete` feature follows clap_complete's dynamic completion, which sits behind clap_complete's `unstable-dynamic` feature and outside clap's semver promise. Its signatures use only clap and the standard library, but what it offers and how a shell registers it may change in a crumbkit minor release, and the changelog names each such change (ADR-0048).

Considered: exit codes 1 and 2 fixed for crumbkit's failures, a place that is a `RuntimeFailing` without a code and panics when it is run, a `RuntimeFailing` generic over a marker type for a place and a line, constructors generic over borrowed and owned codes, `parse` returning an `ExitCode` and a separate function that finds `--json`, a `Stop` with its own `is_json` and no `Output`, public-field structs, a feature-gated schema bound, `Call` methods hidden from the docs, holding the `complete` feature back until clap_complete's dynamic completion is stable.

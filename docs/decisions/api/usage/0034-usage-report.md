# ADR-0034. Usage report

- `self usage` reads the tool's usage log (ADR-0029) and reports the patterns where callers waste effort. It sits behind the `usage-log` feature. A tool adds a `self` group with a `usage` subcommand that flattens `crumbkit::usage::SelfUsage`, and its handler passes `crumbkit::usage::findings` to `finish` with the document `SELF_USAGE`. shelf shows the wiring.
- `--since` takes a humantime duration and defaults to `7d`. The report reads the runs that ended in that duration before now, and the summary names the UTC day on which the duration starts.
- The report reads the log once, a line at a time, and holds at most 1,025 bytes of a line, which is the longest record and its newline. It keeps counts per command and what each session's findings need of its earlier runs, and never a copy of the file. A line that is not a whole `crumbkit/usage/v1` record is skipped. On a 10 MB log of about 29,000 records, the release build of shelf runs `self usage` in about 45 ms, which includes the trim that the run's own log line causes.
- The report has eight findings. Each counts runs under one command path.
  - `one id at a time`: a session ran a command that takes ids with one id at least 3 times within 120 s.
  - `identical repeat`: a session ran the same command line again within 60 s.
  - `help loop`: a session read at least 3 help pages before its first successful run, or without one.
  - `usage error`: the parser refused the command line. The row names clap's nearest flag when the record has one.
  - `retry after failure`: a session ran a command again within 60 s of its failure. The row names the failure's code.
  - `short page`: a session followed a cut-short listing within 60 s with the same command and `--all` or `--limit`. The record holds no limit value, so any `--limit` counts, also one that asks for fewer rows than the default page.
  - `heavy output`: the 95th percentile of a command's output is at least 20,000 bytes, which is about 5,000 tokens of a coding agent's context.
  - `slow command`: the 95th percentile of a command's wall time is at least 1,000 ms.
- The report checks each record against the tool's command tree before it counts it. The command path must name real subcommands by their names, so an alias path fails. Each flag and the nearest flag must be a long name of the command's arguments, or a short name of an argument without a long one. A code must be 1 to 128 ASCII letters, digits, `_`, `-`, `:`, `.` and `/`, so a code in a predefined spelling or a custom one passes, and a code with whitespace or any other character fails. A caller must be `person`, `unknown` or an id that is-ai-agent gives. A record that fails a check is left out and counted in the summary's `skipped`, so a hand-edited line cannot put its text in the report.
- The output is a listing whose rows are the findings, the most runs first. Text prints a summary line above the table, such as `1,284 runs in 23 sessions since 30 Sep: claude-code 1,201, person 83.` JSON is the `crumbkit/self-usage/v1` document, checked in as `crates/crumbkit/schemas/self-usage-v1.json`, with the summary's runs, sessions, callers, since day and skipped count under `summary` (ADR-0016). With `--json --full`, each row also holds the figures of its command, such as its runs, failures and 95th percentiles, and the `Next:` line points there. A command without a finding has no row, so `--full` gives no figures for it.
- A tool that never called `Output::set_command` has no name to find its log by, and a log that is missing or unreadable reads as empty. Either way the report has no runs and exits 0, as every usage-log failure stays silent.
- shelf's tests write a log of wasteful runs through the binary and compare the text and `--json --full` output with golden files. One test checks that the report holds no value that the runs typed and no hash, and another plants four edited records and checks that the summary counts them as skipped. `check_examples` exempts `self usage`, because its output names the current day.

Considered: a summary as an extra row, a separate summary document beside the listing, reading the log into memory, a report that fails on a missing log, a check of codes against the predefined spellings only, a check of codes against the tool's own spelling, a `--since` in days only, a hidden `self` group.

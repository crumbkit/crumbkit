# ADR-0016. Result formats

- Results come in two formats: compact text for people and agents, and JSON for programs ([`finish`](../../../../crates/crumbkit/src/output.rs)). The text table already has a header row, one record per line and no repeated keys.
- No command prints Markdown. `cargo crumbkit docs` writes a Markdown reference of a tool's commands to a file (ADR-0044), and `commands list` exports a branch of the command tree in these two formats (ADR-0026).
- A type that prints as a table row implements [`Row`](../../../../crates/crumbkit-core/src/row.rs), which names its compact columns and the columns that `--long` adds, and a field in neither list appears only with `--json --full`.
- The text table pads columns by characters and escapes control characters, so each row stays on one line and no line ends in padding. Cell widths count characters, so a wide character misaligns a column.
- The [`Output`](../../../../crates/crumbkit/src/output.rs) flags are global. An unknown `--fields` name is refused before anything prints (ADR-0001).
- A command that prints rows as they arrive opens a stream with `stream` (ADR-0041). A tool that prints more than one result through `finish`, such as a child process's output, reads `Output::is_json` to follow the caller's format. The answer exists on every path, because `parse` returns a `Stop` whose `Output` holds the `--json` that the walk found (ADR-0021). A command that hands the terminal to a child process uses the `child` module, which reads a child's JSON as a declared document (ADR-0042).
- A tool draws progress with a library of its choice, and only when `Output::progress_allowed` is true: `--json` is off and standard error is a terminal. A program, an agent, a pipe, a file and crumbkit-test's `check_examples` therefore never receive progress lines, and crumbkit takes no progress library as a dependency.
- A command that may show fewer rows than matched flattens [`Page`](../../../../crates/crumbkit/src/page.rs), so the paging flags belong to that command and its `--help` shows its own default limit. crumbkit implements `Serialize` and `JsonSchema` for `Page` by hand, so a build without the `usage-log` feature needs no serde or schemars derive macros. The `usage-log` feature enables both derives for the usage record (ADR-0029).
- Such a command returns a [`Listing`](../../../../crates/crumbkit-core/src/listing.rs). `Listing::new` takes a total that the tool counted itself, so a handler never loads a row it will not print.
- When a listing shows fewer rows than its total, a footer on standard output says so and names `--all`. crumbkit owns the wording, and the tool supplies only the description.
- A listing may carry one next step and a note, which print in text only. A next step whose `Call` does not resolve is left out, so crumbkit never prints a command the tool hid.
- A listing may carry a summary of the whole result. Its type is the listing's second type parameter and implements `Serialize` and `Display`, so the text output prints it as one line above the table and the JSON document holds it as an object under `summary`. A listing without a summary writes no `summary` field.
- A failure prints as text on standard error, with nothing on standard output, or with `--json` as one failure document on standard output. In text, each alternative repair prints on its own `help:` line after the recovery's.
- With the `miette` feature, each label of a failure's diagnostic prints with its source line and a caret underline, drawn by crumbkit.
- A command that takes many ids returns a [`Batch`](../../../../crates/crumbkit-core/src/batch.rs). The rows print on standard output and the failures on standard error, and with `--json` both go into one document (ADR-0007). A batch with at least one failure exits with code 1.
- A command whose answer is a few sentences returns a [`Prose`](../../../../crates/crumbkit-core/src/prose.rs), whose value implements `Display`, `Serialize` and `JsonSchema`. The text output prints the `Display`, and the JSON document holds the value under `data`, so a person reads sentences and a program reads fields that a schema describes.
- A prose result may hold failures, which print and exit as a batch's do and sit under `failures` in its document, so a command can answer for the ids it found and fail for the rest. `failures` is present even when it is empty, as a batch's is.
- The text of a prose result keeps its line feeds and tabs and escapes every other control character, so a value from the data cannot send a terminal escape sequence. crumbkit adds a final line feed when the text lacks one and prints nothing for an empty text.
- `--fields` is refused for a prose result with exit code 2, because it has no columns to select, and the hint names `--json`. `--long` and `--full` leave a prose result unchanged, because it has no long columns and `--json` already prints its whole value.
- A command that keeps the shape of an existing document prints a document from `Document::without_envelope`. With `--json` it prints the result alone with every field: a row as an object, a list, listing or batch as an array, and a prose result's value. `--fields` selects fields as it does for any other document, and `--long` and `--full` change nothing in its JSON. A listing prints one page without `total`, and its text output keeps the footer and next step. The failures of a batch or prose result print as text on standard error even with `--json`, and the command exits with code 1. A command that fails as a whole still prints the failure document, so every command fails in one shape. crumbkit-test's `check_document_ids` requires an opt-out for each such command (ADR-0036).
- A dry run's text output ends with `This was a dry run, so nothing changed.` on standard output. An unwrapped document's JSON prints unchanged on a dry run, and the line goes to standard error (ADR-0039).
- `finish` writes through a [`Sink`](../../../../crates/crumbkit/src/sink.rs), and `finish_to` writes into a given sink, so tests run in memory. A pipe that the reader closed early keeps the exit code of the result.
- A tool with a `FailureForm` prints each failure and refusal in that form, in text and with `--json` (ADR-0045).

Considered: a progress API in crumbkit, progress that also checks `TERM`, a failure on standard output without `--json`, TOON, a Markdown result format, unicode-width for cell widths, serde_json's `preserve_order` feature for column order, global paging flags, the footer on standard error, the description in the JSON document, the note in the JSON document, a summary as text only, a summary held as a JSON value, deriving `Serialize` and `JsonSchema` for `Page`, failing a whole many-id command when one id fails, a summary line after a batch's failures, a batch's failures on standard output in text, a separate exit code for a batch in which some ids worked, carets measured with unicode-width, a one-column row for an answer in prose, a listing with a summary and no rows, a plain string result, `--fields` selecting the fields of a prose value, `failures` only in a prose document that can fail, a prose text printed without escaping, a separate `finish` for unwrapped documents, a wrapper result type for them, every failure of an unwrapped command as text, `--fields` refused for an unwrapped document.

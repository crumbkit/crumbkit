# ADR-0052. JSON layout

- With `--json`, every whole JSON document prints on one line by default, whether or not standard output is a terminal, so a run prints the same bytes at a terminal and through a pipe (ADR-0049). An agent reads the fewest tokens, and a program reads each document with one line read.
- A tool whose readers need indented JSON sets `Guide::json_layout(JsonLayout::Pretty, reason)`. crumbkit then puts each field and each item of a whole document on a line of its own, indented by two spaces for each level, byte for byte as serde_json's pretty formatter writes it.
- crumbkit serializes every document on one line through `&mut dyn Write`, and with `Pretty` it re-indents those bytes with a plain function. The compiler then generates each document's serialization code once for every writer and both layouts. serde_json's pretty formatter would generate it a second time and made shelf's stripped binary 7.5% larger, including for tools that never set the layout. The setting covers the envelope, a document from `Document::without_envelope`, the failure document, a refusal's failure document and the document of a failure form (ADR-0045). The setting applies at a terminal and through a pipe alike, so OUTPUT-1 holds.
- A stream prints one document per line in every layout, including a failure that ends the stream, because a reader of JSON Lines reads one line at a time (ADR-0041).
- `JsonLayout` is a `#[non_exhaustive]` enum with the single variant `Pretty`. A tool without the setting has no layout, so a `Compact` variant would only name the default. A later layout, such as another indent width, adds a variant without breaking a tool.
- The output budget counts the bytes as printed, so with `Pretty` it counts the indented bytes, and a listing cut by the budget fits fewer rows (ADR-0046). Indenting made the JSON documents of shelf's examples 20 to 62 percent larger.
- crumbkit-test's `check_opt_outs` lists the layout as `json-layout/pretty` with the tool's reason and that cost (ADR-0036). `check_examples` reads the guide's layout: with `Pretty`, a `--json` example of a leaf of one result must print exactly one document whose second line is indented by two spaces, and a stream keeps one document per line. The failure reader of the recovery and twin checks and `check_output_budget` read a document on one line or indented.
- The `--json` help text says "Print the result as a JSON document" and names no layout, because the layout belongs to the tool.

Considered: serde_json's pretty formatter, a formatter that wraps it, an indented default at a terminal and one line through a pipe, a `Compact` variant, a choice of serde_json formatter or indent width, a budget counted in the bytes of the one-line form, a separate pseudo-terminal golden file for indented output, an environment variable or a flag that picks the layout.

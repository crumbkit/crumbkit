# ADR-0042. Child processes

- A command that runs another program as its whole job, such as opening an editor or a pager, hands the terminal to it through [`child::hand_over`](../../../../crates/crumbkit/src/child.rs). The child inherits standard input, output and error, and receives the variables of `trace::child_env`, so it joins the run's trace (ADR-0030). The module sits behind the `hand-over` cargo feature, which is off by default and adds signal-hook on Unix (ADR-0003).
- The tool returns the child's exit code, so on such a command 1 and 2 carry the child's meanings (ADR-0002). A child that a signal ended returns 128 plus the signal's number, as a shell reports it, and the usage log records the code and `"interrupted": true` (ADR-0029).
- On Unix the tool ignores SIGINT and SIGQUIT while the child runs, as POSIX `system()` does, so Ctrl-C reaches only the child. The tool installs a signal-hook handler that takes the default action when no child runs, because a handler resets to the default action when the child starts its program and an ignored disposition would stay ignored in the child. When the usage log listens for SIGINT, crumbkit installs no SIGINT handler, and the log's signal thread skips SIGINT while a child holds the terminal.
- On Windows the tool keeps Ctrl-C's default action, so Ctrl-C ends the tool beside the child. A RUST-10 comment at `hand_over` records this, because crumbkit supports only Linux and macOS (ADR-0003).
- A child with a JSON form goes through `hand_over_json` with a `child::Json` constant, which names the arguments that make the child print JSON and the document that the output is read as. Under `--json`, crumbkit adds those arguments, reads the child's standard output as that document's type and prints it as `finish` prints a result, so `--fields`, `--long` and `--full` work as on any command. Standard input and standard error stay the tool's, so the child can still ask a question or report a problem.
- `--json` on a command whose child has no JSON form fails with `crumbkit::child::no_json` and exit code 2 before the child runs. The refusal happens when the command runs, so help still lists the global `--json`. `--fields` without `--json` is refused with `crumbkit::cli::usage` and exit code 2, because the child's own text has no columns.
- A program that does not exist fails with `crumbkit::child::not_found` and a hint to install it, and one that the operating system refuses to start fails with `crumbkit::child::not_started`, both with exit code 1. Under `--json`, a child that exits with a code other than 0 fails with `crumbkit::child::failed` and returns the child's code, and output that is not the declared document fails with `crumbkit::child::bad_json` and exit code 1 (ADR-0001).

Considered: a `--json` refused by clap through a per-command flag, which changes help, a child's JSON passed through without parsing, a fixed exit code for a child that a signal ended, `SIG_IGN` for SIGINT, a handler that forwards SIGINT to the child, the `hand-over` code in the default build, a pager API with its own environment variables.

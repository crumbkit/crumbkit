# ADR-0042. Child processes

- A command that runs another program as its whole job, such as opening an editor or a pager, hands the terminal to it through [`child::hand_over`](../../../../crates/crumbkit/src/child.rs). The child inherits standard input, output and error, and receives the variables of `trace::child_env`, so it joins the run's trace (ADR-0030). The module sits behind the `hand-over` cargo feature, which is off by default and adds signal-hook (ADR-0003).
- The tool returns the child's exit code, so on such a command 1 and 2 carry the child's meanings (ADR-0002). A child that a signal ended returns 128 plus the signal's number, as a shell reports it, and the usage log records the code and `"interrupted": true` (ADR-0029).
- On Unix the tool ignores SIGINT and SIGQUIT from the moment the first child starts until the tool ends, so Ctrl-C reaches only the child. The tool installs a signal-hook handler that takes the default action until then, because a handler resets to the default action when the child starts its program and an ignored disposition would stay ignored in the child. A handler acts when a signal reaches one of the tool's threads, and a Ctrl-C sent while the child ran can reach a thread after the child has exited. A handler that took the default action again at that point would end a tool with more than one thread, so the tool keeps ignoring both signals. A command hands the terminal over as its last step, so only the result, the usage log's line and the exit remain. When a usage log runs, its signal thread has already taken SIGINT, so crumbkit installs no SIGINT handler. With `Signals::Crumbkit` the log's thread skips SIGINT once a child has held the terminal, and with `Signals::Tool` the tool's own handler decides, whether or not a child runs.
- On Windows the tool ignores SIGINT and SIGBREAK while the child runs, which the C runtime raises on Ctrl-C and Ctrl-Break, so both reach only the child. The handlers come from signal-hook's `register_conditional_shutdown`, which ends the process with `STATUS_CONTROL_C_EXIT` when no child runs, the exit code that either key gives a process without a handler. The tool takes the default actions again once the child exits. A Ctrl-C that reaches the handler after the child exits may end the tool as it could on Unix, which nobody has tested on Windows. A Windows child inherits no handler of the tool. A child that exited with `STATUS_CONTROL_C_EXIT` counts as ended by SIGINT, so the tool returns 130 and the usage log records `"interrupted": true`. Closing the console, logging off and shutting down still end the tool beside the child, because the C runtime raises no signal for them (ADR-0003).
- A child with a JSON form goes through `hand_over_json` with a `child::Json` constant, which names the arguments that make the child print JSON and the document that the output is read as. Under `--json`, crumbkit adds those arguments, reads the child's standard output as that document's type and prints it as `finish` prints a result, so `--fields`, `--long` and `--full` work as on any command. Standard input and standard error stay the tool's, so the child can still ask a question or report a problem.
- `--json` on a command whose child has no JSON form fails with `crumbkit::child::no_json` and exit code 2 before the child runs. The refusal happens when the command runs, so help still lists the global `--json`. `--fields` without `--json` is refused with `crumbkit::cli::usage` and exit code 2, because the child's own text has no columns.
- A program that does not exist fails with `crumbkit::child::not_found` and a hint to install it, and one that the operating system refuses to start fails with `crumbkit::child::not_started`, both with exit code 1. Under `--json`, a child that exits with a code other than 0 fails with `crumbkit::child::failed` and returns the child's code, and output that is not the declared document fails with `crumbkit::child::bad_json` and exit code 1 (ADR-0001).

Considered: a `--json` refused by clap through a per-command flag, which changes help, a child's JSON passed through without parsing, a fixed exit code for a child that a signal ended, `SIG_IGN` for SIGINT with a reset in the child before it starts its program, which needs unsafe code, restoring the default actions on Unix once the child exits, a handler that forwards SIGINT to the child, the `hand-over` code in the default build, a pager API with its own environment variables, a Windows console control handler through `windows-sys`, Windows exit codes passed through as they are.

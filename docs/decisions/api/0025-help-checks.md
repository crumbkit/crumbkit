# ADR-0025. Help checks

- crumbkit-test's `check_help_sizes(command, guide, budgets)` and `check_help_goldens(command, guide, dir)` read the help pages that crumbkit prints. For each page, they run `crumbkit::parse_to` on a clone of the tree with the tool's guide and the words `<tool> <path...> -h` or `<tool> <path...> --help`, and capture standard output through a `Sink` over `Vec<u8>`. The page is therefore the plain text that a caller reads on a pipe, with goal headings, leaf examples, columns and crumbkit's `Global flags:`, `Topics:` and `Next:` lines.
- The help checks visit the root and every visible command below it, and skip each hidden command and everything below it, because no help page shows them. They parse into `()`, for which clap implements `FromArgMatches`, so they need no type of their own. They take no exemptions, because a tool sets a budget per command and pins every page.
- A budget counts the bytes of the plain-text `-h` page, which agents read first and most often. `--help` has no budget, because a caller asks for it to read the full descriptions and the columns. The default budgets are 1,500 bytes for the root, 800 for a group, which is a command below the root with subcommands, and 1,200 for a leaf, which is a command below the root without subcommands. The root of a tool without subcommands uses the root budget.
- `Budgets` is a `const fn` builder with private fields (ADR-0002). `Budgets::new()` holds the defaults, `.root(bytes)`, `.group(bytes)` and `.leaf(bytes)` lower a whole class, and `.nodes(&[("books list", 600)])` lowers single commands, each named by its path below the root as the other checks' exemptions name commands. A command's own budget wins over its class budget.
- `check_help_sizes` fails on a page over its budget, naming the path, the size and the budget. It fails on a class or command budget above crumbkit's default for that class, because a tool can lower a budget and cannot raise one, and on a command budget whose path names no command or a hidden one.
- `check_help_goldens` compares each page with a file in `dir` through snapbox (ADR-0004). The root's files are `<tool>-h.txt` and `<tool>-help.txt`, and another command's files join its path with dashes, such as `shelf-books-list-h.txt` and `shelf-books-list-help.txt`. A relative `dir` resolves from the package's manifest directory, because cargo runs a package's tests there.
- Without `SNAPSHOTS=overwrite`, `check_help_goldens` fails on a missing file, a file whose content differs, and a stale file, which is a `.txt` file in `dir` that no visited page produces. `dir` therefore holds only help golden files. It collects every problem through snapbox's `Assert::try_eq` and reports them at once, as the other checks do. With `SNAPSHOTS=overwrite`, it writes and rewrites the files and deletes each stale file.
- `check_guide` holds the leaf rules: a visible command without subcommands that no leaf with an example names, a leaf column that is not a field of the row type, and a leaf column without a description (ADR-0024). The column rules read `Leaf::column_descriptions`, which builds the row type's JSON Schema and returns each column as a `help::Column`, and a leaf's `--help` reads its columns through the same method.
- crumbkit-test has no bundled check that runs every check. Each check has its own settings and a tool calls each from its own `#[test]`, so a failure names the rule that broke.

Considered: measuring clap's `render_help` after `extend`, a plain `&[(path, bytes)]` slice of node budgets, a budget on `--help`, leaf rules in a separate `check_leaves`, a bundled `check(command, guide)`.

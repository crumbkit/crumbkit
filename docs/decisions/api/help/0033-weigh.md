# ADR-0033. Help weight

- The published crate [cargo-crumbkit](../../../../crates/cargo-crumbkit/README.md) holds the binary `cargo-crumbkit`, so `cargo crumbkit weigh --bin <NAME>` measures a tool. cargo-crumbkit is a crumbkit tool itself: it parses with `crumbkit::parse`, prints the `crumbkit/weigh/v1` document through `finish`, mounts `commands list`, has its own failure codes, and runs crumbkit-test's checks on its own help.
- `weigh` builds the named binary with `cargo build --workspace --bin <NAME> --message-format json` and takes the executable from cargo's messages. cargo's standard error goes to `weigh`'s own, so a person sees cargo's progress lines and compiler errors as with any cargo subcommand. It reads the command tree from `<binary> commands list --all --json --full`, and a tool without `commands list` fails with `crumbkit::weigh::no_commands_list`, whose hint says how to mount it.
- `weigh` runs `<binary> <path> -h` and `<binary> <path> --help` for each visible command and counts the bytes on standard output. Each run has a cleared environment and fresh XDG directories, as crumbkit-test's `check_examples` gives each example (ADR-0005), so `weigh` never reads a person's aliases or writes to their usage log.
- A command's output weight is the size of the largest golden file of its examples, read from `--goldens <DIR>` or from `tests/golden/examples` in the binary's package. `weigh` names each file with crumbkit-test's `example_golden_name`, the function that `check_examples` uses, so the two cannot disagree. A command without a golden file has no output weight, shown as `-` in text and `null` in JSON.
- A command's path total is the sum of every `-h` page from the root down to the command plus the command's output weight. A plain function over the rows computes it, so a later check can set budgets on path totals.
- Every weight is a byte count. The text table prints byte counts and each command's full path, because crumbkit's table prints numbers as JSON does and has no tree drawing. The JSON rows are in depth-first order from the root with their fields in a fixed order, so CI or an agent can compare two runs by diffing the output.

Considered: an HTML report, token counts, a `--compare` flag, an in-process library form that reads the clap tree without building the binary, sizes in KB, tree prefixes such as `├─` in the text table.

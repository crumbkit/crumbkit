# ADR-0037. Exit codes

- A tool declares the exit codes it returns besides crumbkit's 0, 1 and 2 in its `Guide`, each an [`Exit`](../../../../crates/crumbkit/src/help/exit.rs) with a one-sentence meaning and, optionally, the command paths that return it. A code without paths covers every command, and a path covers its command and every command below it. The declaration lives on the `Guide`, because most codes apply to many commands.
- An `Exit` lists failure codes with `Exit::failures`, and a run whose first failure has a listed code exits with that code in place of 1, in `finish`, a batch, a prose result and a stream alike. The first failure decides because the usage log and the `crumbkit.finish` span record its code, so a recorded `code` explains its `exit` (ADR-0029). The guide holds the mapping beside the meaning, so crumbkit-test can predict each run's exit.
- `Output::set_command` copies the exits from the `Parsed` of `parse` or `Parsed::guided`, so a bare `Command` maps no failure. A code from `Code::runtime` cannot be listed, so its failure exits with 1.
- `<tool> help exit-codes` lists crumbkit's codes, then the tool's, and says that a shell reports 126 and above for its own reasons (ADR-0023). `commands list` gives each row the codes that cover its command, and its text table ends with a note that names the codes and the topic (ADR-0026).
- A tool that another program runs with fixed words sets `Guide::root` to the path of the command that callers run first. cargo runs `cargo crumbkit help` as `cargo-crumbkit crumbkit help`, so cargo-crumbkit's clap root is `cargo` and its guide's root is `crumbkit`. That command answers `help` with the topics and its help has the `Topics:` line. The topic lines and the `commands list` note start with the clap root's name and the root's path, such as `cargo crumbkit help exit-codes`, so every printed command runs. `check_guide` reports a root that names no command, and `parse` then uses the clap root.
- crumbkit-test's [`check_exit_codes`](../../../../crates/crumbkit-test/src/exits.rs) reports a declared code from 0 to 2, a duplicate code, an empty or multi-line meaning, and a path that names no command. A code from 126 to 255 needs an opt-out of `exit-codes/shell-code` that covers every command returning it (ADR-0036). A code from 0 to 2 has no opt-out, because crumbkit's meaning of the code would contradict the tool's. crumbkit never checks the declarations at run time, so a wrong declaration cannot end a run.
- `self usage` and `self figures list` count each command's runs that exited with each code from 3, with the meaning that the guide declares for that command, or null (ADR-0034).

Considered: a `Failure::exit` method, an exit code passed to `end` and `finish`, the last failure choosing the exit, listed failure codes in `help exit-codes`, renaming cargo-crumbkit's clap root `cargo crumbkit`, which clap would print as one word, a full invocation string in place of a path, exit codes declared on each leaf, a declared code that must name its commands, a runtime check of the declarations, an opt-out for codes from 0 to 2.

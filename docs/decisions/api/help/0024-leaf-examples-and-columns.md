# ADR-0024. Leaf examples and columns

- A tool declares its leaves in its `Guide` with `.leaves(&[...])`. Each `Leaf::new(&["books", "list"])` names a command by the real names of its subcommands from the root, as `Group::new` does, and takes `.examples(&[Example::new(&["--all"], "Print every book")])` and `.document(BOOKS_LIST)`. An example holds the words after the leaf's path and a one-line description, and the document is the constant that the tool passes to `finish`.
- `Leaf::document` keeps the row type's `Row::COLUMNS`, its `Row::LONG_COLUMNS` and a function pointer that builds its JSON Schema. `Leaf` therefore has no type parameter, and one guide holds leaves whose rows have different types.
- A leaf's `-h` lists the examples under `Examples:` after the options, one full command line each, such as `shelf books list --all`. The `Global flags:` line of ADR-0021 follows after a blank line, and a leaf with a document ends with `Next: shelf books list --help explains each column.`
- A leaf's `--help` lists each example in clap's layout of long options: the command line at two spaces, its description on the next line at clap's indent of ten spaces, and a blank line between examples. `Columns:` lists `Row::COLUMNS` and `Columns that --long adds:` lists `Row::LONG_COLUMNS` in declared order and in the layout of the goal list, and a section with no names is left out. `--help` on a leaf has no `Global flags:` line and no `Next:` line.
- A column's description is the `description` of its property in the row type's JSON Schema, which schemars takes from the field's doc comment, so the doc comment is the only place a column is described. Only the first paragraph prints, and a column without a description, a column whose name is not a property, and every column of a schema without properties print the name alone.
- `parse` builds the schema only when `--help` appears in the typed words before any `--`, including after its `help` rewrite (ADR-0023), so a run that prints no long help never builds it. An option value spelled `--help` makes `parse` build the schema for a page that clap does not print, which costs time and changes no output.
- An example's word that a POSIX shell would split or expand prints between single quotes, with an embedded `'` written as `'\''`. A word made only of ASCII letters, digits and `-_./:,=+@%` prints as it is. The quoting suits the POSIX shells of crumbkit's supported platforms, and a rendering for each shell replaces it if crumbkit supports Windows.
- `parse` applies a leaf only to the deepest command on the walked path, as part of the walk of ADR-0021, and finds it by comparing each leaf's path with the walked path. `help::extend` applies every leaf's examples to the whole tree and adds no columns and no `Next:` line, because it cannot know whether help will print. The runtime never fails on a leaf: a leaf whose path names no command is skipped, and of two leaves with one path the first applies.
- crumbkit-test's `check_guide` fails on a leaf path that names no command, a leaf path that names a command with subcommands, two leaves with one path, and an example that clap refuses. It clones the tree once and parses the tool's name, the leaf's path and each example's words with `try_get_matches_from_mut`, and it reports clap's error kind and the example's command line. An example that asks for `--help` or `--version` counts as refused, because an example shows a real run.

Considered: a string path such as `Leaf::new("books list")`, a `#[command(after_help)]` attribute per leaf, a separate column-description list beside `Row::COLUMNS`, building the schema on every run.

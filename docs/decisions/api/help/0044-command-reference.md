# ADR-0044. Command reference

- The published crate [crumbkit-markdown](../../../../crates/crumbkit-markdown/README.md) writes a Markdown reference of every command of a tool. Its `render` reads the `crumbkit/commands-list/v1` document that `<binary> commands list --all --json --full` prints and returns one CommonMark file. The document is the export that ADR-0026 made for other programs, so the reference needs no access to the tool's code and says what the tool's help says. crumbkit-markdown depends on serde and serde_json to read the document, and on crumbkit only for `Effects::line` and `help::STREAM_LINE`, so the effects and stream lines use help's own wording.
- The reference is one file. It opens with the title `Commands of <root>` and a line saying that crumbkit-markdown writes it from the tool's help. Each command then has a section in the document's depth-first order. The heading is the command line in a code span. The section holds the long description, a `Commands` list that links to each subcommand, an `Arguments` list, the examples as fenced `sh` blocks, the columns and the columns that `--long` adds, the effects line, the stream line, and an `Exit codes` list. Each argument item ends with the facts that help shows: whether it is required or what can be given in its place, whether it takes several values, its possible values, its defaults, and whether it works after every subcommand.
- The reference escapes the inline markup characters of help text and the block markers at the start of a line, and keeps its code spans and line breaks. Help text is plain text, so a character such as `*` or `<` prints as written.
- A link to a command uses the anchor that GitHub gives its heading: the text lowercased, spaces turned into dashes, and other punctuation dropped. `render` fails when two commands, or a command and the title, have one anchor, because a link to the second would reach the first. It also fails on a document that holds one page of a longer listing, so the reference never leaves a command out.
- `cargo crumbkit docs --bin <NAME>` builds the binary as `weigh` does (ADR-0033), runs it with a cleared environment and fresh XDG directories, and writes the reference to `docs/commands.md` in the binary's package, or to `--out <FILE>`. It prints the `crumbkit/docs/v1` document, which names the file and the number of commands. Its failures share the `crumbkit::tool::*` codes of building and running the binary with `weigh`, and add `crumbkit::docs::unrenderable` and `crumbkit::docs::write_failed`.
- crumbkit-test's `check_command_reference` runs the binary's `commands list` in the same way, renders the reference and compares it with the checked-in file. `SNAPSHOTS=overwrite` writes the file, as it does for every golden (ADR-0004). A tool that checks in its reference adds this test, so a change to its help that leaves the reference stale fails CI. The shelf example checks in `examples/shelf/docs/commands.md`.

Considered: one file per command, a reference read from the clap tree in process, a template engine, a Markdown library that escapes text, a list of anchors without links, a reference that keeps Markdown written in help text, `--check` on `cargo crumbkit docs`, the document id of each command's output, help topics in the reference.

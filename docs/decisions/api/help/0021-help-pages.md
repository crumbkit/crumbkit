# ADR-0021. Help pages

- `crumbkit::parse` keeps the help template of each command and adds crumbkit's lines after it, through `after_help` for `-h` and `after_long_help` for `--help`. A command's own `after_help` and `after_long_help` print first, and crumbkit's lines follow them after a blank line. It adds them only to the commands that the typed words pass through, and the deepest of those commands also gets the examples and columns of its leaf (ADR-0024). crumbkit's extra work on every run grows with the depth of the command typed, and the command tree is never cloned.
- crumbkit hides the root's visible global flags from `-h` with `hide_short_help`, and `-h` ends with one line that names them in definition order, such as ``Global flags: --json, --fields <FIELD>, --long, --full. `shelf books list --help` describes them.`` `--help` lists the flags in full and leaves the line out. clap still prints `[OPTIONS]` in a usage line whose options are all hidden from `-h`.
- The help of a command with a visible subcommand ends with a `Next:` line built from the command's path and its subcommand value name, such as `Next: shelf books <COMMAND> -h`, in `-h` and `--help`. A command whose subcommands are all hidden, or that has none, has no `Next:` line yet.
- Help and the version print on standard output and exit with code 0, also when the reader closed the pipe early. `parse` and `parse_from` print them through clap's `Error::print` when standard output is a terminal, which keeps clap's colours when the tool enables clap's `color` feature. They print plain text otherwise, and `parse_to` always prints plain text.
- crumbkit finds the deepest command the caller reached by walking the typed words once before parsing: it skips the program name, stops at `--`, skips each flag and each value of an option, and descends with `find_subcommand`, which resolves aliases and finds hidden commands. It reads an option's values from clap's `Arg` for the command it has reached and the global arguments above it, in the forms `--opt value`, `--opt=value`, `-o value` and `-ovalue`, up to the option's `num_args`, so an option's value that equals a subcommand name names no command.
- A tool may list a group's subcommands under goal headings that it declares, such as `Read` and `Change`, in place of clap's single `Commands:` list. It declares a `const` `Guide` of `Group`s, each a command path from the root with its `Goal`s and each goal a heading and the real names of its subcommands, and passes it to `parse`, which applies the goal headings only to the guided groups that the typed words pass through, the commands that get crumbkit's lines. `help::extend(command, &guide)` applies them to the whole tree for a tool that parses with plain clap and for tests, through the same per-group function as `parse`.
- A guided command gets clap's default template with the list in `{before-help}` in place of `{all-args}`, followed by an `Options:` heading and `{options}`, and `--help` falls back to the same `before_help`. clap expands no tags in `before_help` other than `{n}`, so a description prints as it is. A guided page has no `Arguments:` section, prints an argument with its own help heading under `Options:`, and loses the tool's own `before_help` and `before_long_help`, and shelf's golden files fail when clap's default layout changes.
- Each line of the list holds two spaces, the name padded to the longest name on the page plus two spaces, and the command's `about`, or its `long_about` when it has no `about`, and a command without either ends its line at its name. Headings have no colon and print in clap's header style, and names print in its literal style.
- The list leaves out hidden commands and names that match no subcommand, and a goal with nothing to list prints no heading. A visible command that no goal names is listed under a final `Commands` heading, and a command that two goals name is listed under both. `parse` and `extend` never fail on a guide. crumbkit-test's `check_guide` fails on a group path that names no command or a command without subcommands, a goal name that is not a subcommand of its group, a visible subcommand that no goal names, and a subcommand that two goals name.
- A command that the guide does not name keeps clap's `Commands:` list. crumbkit's `after_help` lines appear on guided and unguided pages alike.
- A refusal's message is clap's rendered error above its `Usage:` line on one line: the `error:` and `tip:` labels and the `For more information` line are dropped, the lines of a paragraph join with spaces, and paragraphs and tips join with `; `. A command line that stops at a command with subcommands prints ``the command `shelf books` needs a subcommand`` in place of clap's help page. The message depends on clap's wording, and shelf's golden files fail when it changes.

Considered: help templates for crumbkit's own lines, crumbkit rendering whole help pages, plain text always, a second parse with errors ignored, rebuilding the message from clap's error parts, applying the whole guide before every parse, hiding a group's children, the list as literal text in the template, a runtime builder holding `Vec`s.

# ADR-0023. Help command and topics

- `crumbkit::parse` answers the word `help` itself and turns off clap's generated `help` subcommand with `disable_help_subcommand`, which clap passes down the tree. clap's `help` line then leaves every `Commands:` list, and `Command::build` no longer copies the tree into a generated help command.
- `parse` answers `help` at every level, as clap's `help` did, because a refused request for help gives the caller nothing. It answers before clap parses, so the tool's own type never sees the word. It reads the words as the walk of ADR-0021 does, descending through the tool's own subcommands, and answers `help` when it is the next word below a command with subcommands, or directly after the program name when the guide has topics, so a tool whose root has no subcommands still answers it when it has topics. It stops at the first word that names no subcommand. Any other command without subcommands reads `help` as an ordinary word, and a command with its own subcommand named or aliased `help` lets clap parse that subcommand.
- At the root, `<tool> help` lists the tool's topics, and prints the root's long help when the tool has none. `<tool> help <TOPIC>` prints the topic's text when the one word after `help` names a topic and no root command or alias has that name. Flags after the topic's name are ignored. Both exit with code 0. Topics belong to the root, so `shelf books help catalogue` names no command.
- Every other `help` command line drops the word `help` and gains `--help` before the first `--`, or at the end, and then parses as usual. `shelf help books show` and `shelf books help show` print what `shelf books show --help` prints, `shelf books help` prints what `shelf books --help` prints, and an unknown word such as `shelf help comets` or `shelf books help shwo` is refused by clap through the usual refusal, with clap's suggestions and the `-h` of the deepest command reached as the recovery. A tool that turns off its `--help` flag gets a refusal.
- A tool declares its topics in its `Guide`, each a `Topic` of a name, a one-line summary and plain text written as a literal or with `include_str!`. crumbkit prints the text as written and adds a final line break when it lacks one.
- `parse` reads the topics from the guide it takes, so the tree holds no topics and no run copies a topic's text. It keeps the first of two topics with one name, and ignores the topics when the root has its own command named or aliased `help`, which then takes the word. A topic named `help` prints, as in `shelf help help`.
- crumbkit-test's `check_guide` fails on a topic name that is not lowercase words joined by dashes, a topic name that a root command's name or alias hides, a topic whose text is empty or only whitespace, and two topics with one name. `check_grammar` fails on a command named or aliased `help` at any level, because crumbkit reserves that word for asking for help. An empty summary passes, and the topic list then shows the name alone.
- The topic list and a topic's text print as plain text, also on a terminal. The list has the heading `Topics`, one line per topic in the layout of the goal list (ADR-0021) and guide order, and ends with `Next: <tool> help <TOPIC>`.
- The root's `-h` and `--help` gain the line ``Topics: catalogue. `shelf help <TOPIC>` prints one.`` after the `Global flags` line and before `Next:`, with the guide's topic names in guide order. A group's help does not show it.

Considered: the hidden `help` command carrying the topics, clap's `unstable-ext` extension slot, a deferred builder per leaf, a `Help` variant in the tool's enum, `help` only at the root, crumbkit writing its own message for an unknown word, topic files read at runtime, a Topics section with summaries on the root page, keeping clap's `help` for tools without topics.

# ADR-0026. Branch export

- `<tool> commands list [PATH]...` lists one branch of a tool's command tree with each command's arguments, examples and columns, so an agent loads a subtree in one call instead of reading its help page by page. `commands` is a resource and `list` its verb, so the command fits the grammar of ADR-0015 as it stands. `CommandsList` flattens `Page`, so the command passes crumbkit-test's `check_grammar`, `check_listings`, `check_filters` and `check_names` with no exemption, and its default limit is 25.
- The tool owns the wiring. It adds a `commands` resource with a `list` subcommand that takes `crumbkit::commands::CommandsList` to its own clap types, and its handler passes `crumbkit::commands::list(&output, &GUIDE, &args)` to `finish` with the document `crumbkit::commands::COMMANDS`. `parse` adds no command and answers none, so a tool that does not want the export leaves it out, and the command's help, goal heading, leaf and examples are the tool's like any other command's. The command sits at the root, because the not-found recovery runs `commands list` below the root.
- `list` reads the command tree that the tool passed to `Output::set_command`, which is the tree that `parse` returns. When no command is set, it fails with the code `crumbkit::commands::unavailable` and a `None` recovery whose reason says that the tool's `main` does not pass its command to `Output::set_command`.
- `PATH` holds the names of the commands below the root, and an alias resolves to the real name. The branch is the command that `PATH` names, or the root without one, followed by every visible command below it in depth-first order in clap's subcommand order. A hidden command and everything below it are left out, as help leaves them out, and `total` counts the visible commands of the branch. The tree that `parse` returns has no `help` subcommands (ADR-0023), and a tree that the tool built itself lists clap's generated `help` subcommands as commands. `list` builds rows for the page only.
- A row holds `path`, the command line that runs the command from the tool's name, such as `shelf books list`; `about` and `long_about`; `arguments`; `examples`; and `columns`. `about` falls back to the long about when the command has no one-line about. A text field that the command lacks is `null`, and a list it lacks is empty, so every row has every field.
- An argument holds `name` as help writes it (`--limit`, `-n` for a short-only flag, or `<ID>` for a positional), `short` such as `-n`, `value_names`, `required`, `many`, `defaults`, `possible_values`, `help`, `long_help` and `global`. `many` is true when the argument takes more than one value per use or appends on a repeat. `value_names`, `defaults` and `possible_values` are empty for a flag that takes no value, a hidden default or hidden possible values stay hidden, and `help` falls back to the long help. An argument's environment variable is left out, because crumbkit does not enable clap's `env` feature and so cannot read it.
- The arguments leave out a hidden argument and the help and version flags. The help and version flags are the same on every command, and clap writes the help flag's text from settings that `parse` changes, so leaving them out keeps the rows the same whether or not the tree went through `parse`. A global argument is listed once, on the command that defines it, or on the branch's first row when a command above the branch defines it, so `shelf commands list books` shows `--json` on `shelf books`. A test proves that the rows are the same from the tree that `parse` returns and from the tree that the tool built.
- `examples` and `columns` come from the leaf in the guide whose path names the command (ADR-0024). An example holds `command`, the full command line with each word quoted as the leaf's help quotes it, and `about`. A column holds `name`, `long`, which is true for a column that `--long` adds, and `description`, the first paragraph of the field's doc comment. A command without a leaf has empty `examples` and `columns`.
- `CommandRow::COLUMNS` is `path` and `about`, and it has no long columns. The text table is therefore a list of command lines with their about texts, and `--json --full` or `--fields` prints the arguments, examples and columns. `--long` adds nothing, because the nested lists would print as compact JSON in a table cell.
- The document id is `crumbkit/commands/v1`, as `crumbkit::commands::COMMANDS`, and its schema is checked in as `crates/crumbkit/schemas/commands-v1.json` (ADR-0007). crumbkit implements `Serialize` and `JsonSchema` for `CommandsList` and the row types by hand, so its normal dependencies stay without derives (ADR-0016).
- A word of `PATH` that names no visible command fails with the code `crumbkit::commands::not_found` in the tool's spelling and the message `` `shelf books shw` names no visible command ``. A hidden command fails in the same way and with the same message, so the failure never reveals a command that the tool hid. Its recovery runs `commands list` with the longest start of `PATH` that names visible commands, such as `shelf commands list books`, through a `Call` that `finish` renders against the tool's command, so the recovery has no next step when the tool hides or lacks `commands list`.
- The two codes are fixed by crumbkit, as `crumbkit::cli::usage` is (ADR-0001), and are not listed in a `CODES` list.
- A Markdown export of help is decided with the documentation (ADR-0013), and `commands list` prints only the two formats of ADR-0016.

Considered: `schema cli [PATH]` with built-in exemptions in the checks, `parse` adding and answering the command itself, one nested tree document, a `--markdown` flag now.

# ADR-0036. Opt-outs

- crumbkit's conventions are the defaults, and a tool can opt out of a rule with a stated reason, so crumbkit meets a tool where it is. An opt-out is an [`Allow`](../../../../crates/crumbkit-test/src/allow.rs) that names one `Rule`, the command it covers with every command below it, and the reason. Each check that takes opt-outs reads only those of its own rules, so a tool keeps one list and passes it to every such check.
- An opt-out skips one rule, or with `Allow::example` one example (ADR-0005). The other rules of the same check still apply to the command.
- A check fails on an opt-out of its rules that names no command or excuses no problem, so the opt-out of a removed or fixed command cannot stay in a tool's list.
- A command that keeps the shape of an existing document declares its document with `Document::without_envelope`, because `finish` and `schemas show` read only the `Document`, and its `Allow` of `Rule::Envelope` carries the reason.
- The rule that reserves `help` has no opt-out, because crumbkit's `parse` answers `help` itself and an opt-out could not change that. A tool that keeps its own `--dry-run` opts out of `Rule::DryRun` with a reason (ADR-0039). A tool that names a person's aliases on its root's help opts out of `Rule::PersonalAliases` (ADR-0027). A tool that can ask a question and has no `--no-input` from `NoInput` opts out of `Rule::NoInput` at its root (ADR-0043). A tool whose failures no test can provoke, or that prints its failures in a failure form, opts out of `Rule::Recoveries` (`recoveries/follow`), and a command whose recovery fails again with the same code on purpose opts out of `Rule::SameCode` (`recoveries/same-code`). A recovery that takes a placeholder's value from a field of its failure, in place of carrying it with `Call::value`, needs an opt-out of `Rule::FieldValue` (`recoveries/field-value`) that names the failing command (ADR-0053).
- A tool pins its opt-outs in a report with [`check_opt_outs`](../../../../crates/crumbkit-test/src/opt_outs.rs), which compares a text and a JSON golden file. Each entry names the rule, the command line, the reason and what skipping the rule costs an agent, and the report also lists each help or path budget that the tool set (ADR-0025) and each guide setting that departs from the conventions with a reason, such as an output budget, a JSON layout or terminal detection turned off (ADR-0046, ADR-0052, ADR-0049), so a reviewer sees a new opt-out as a change to the golden files and an agent reads the JSON to learn where the tool departs from crumbkit's conventions. The report is a test check only, because a tool's opt-outs live in its tests.
- The checks without opt-outs keep their reasons: a tool declares its verbs to `check_grammar`, a tool that wants clap's list for a command leaves the command out of its guide (ADR-0021), `check_mounts` exists to keep crumbkit's commands at fixed paths (ADR-0035), `check_codes` keeps failure codes unique, and the name rule of a failure's fields has no opt-out, because the failure document's schema promises every reader that rule (ADR-0007).
- A tool that prints its failures in its own `FailureForm` opts out of `Rule::FailureForm` at its root (ADR-0045).

Considered: exemptions as bare command paths, an exemption that skips every rule of a check, one constructor per rule in place of a public `Rule` enum, an opt-out that covers its command alone, an opt-out from the reserved word `help`, a `cargo crumbkit` command that prints the report.

# Standards

Each rule states what crumbkit's own code does and the gate that enforces it:
a lint, an xtask check, or review where no tool reaches. A rule that cites a
decision record leaves its reason to that record in `docs/decisions/`, and a
rule that cites none states its reason itself.

## Rust

- **RUST-1.** Code builds without warnings (ADR-0009). The lints are in the root `Cargo.toml`, and every package inherits them through `[lints] workspace = true`. Gate: `CARGO_BUILD_WARNINGS=deny cargo clippy --workspace --all-targets`, and the same with `-p crumbkit --all-targets` alone, with `--features miette` and with `--features tracing`, and on Windows the workspace run in the `windows` job of `scheduled.yml` (CI-4); ADR-0011 says which code each build covers.
- **RUST-2.** Code contains no `unsafe` (ADR-0009). Gate: rustc's `unsafe_code` at `forbid`.
- **RUST-3.** Code suppresses a lint only with `#[expect(lint, reason = "...")]` (ADR-0009). Gate: clippy's `allow_attributes` and `allow_attributes_without_reason`.
- **RUST-4.** Environment, process, standard stream and file-write calls happen only in the module that owns each effect, which suppresses the lint with `#[expect]`, and other code takes a writer or a value (ADR-0009). In the crumbkit crate, `Sink` owns standard output and standard error, the `agent` module owns the environment and file reads that detect a coding agent (ADR-0043), the `complete` module owns the reads of the completion variable and the current directory that answer a shell's completion request, and the read that stops `events::observe` during one (ADR-0048, ADR-0057), and the one exception is `parse`, which lets clap's `Error::print` write help and the version to a terminal so that they keep clap's colours (ADR-0021). The crumbkit-usage crate owns the usage log's environment reads, files, signal thread and the check of whether standard input is a terminal (ADR-0029). The crumbkit-child crate owns running a child process and the tool's SIGINT and SIGQUIT handlers while it runs, or its SIGINT and SIGBREAK handlers on Windows (ADR-0042, ADR-0058). Gate: clippy's `disallowed_methods` with the list in `clippy.toml`, and `print_stdout`, `print_stderr` and `dbg_macro`.
- **RUST-5.** Code outside tests returns errors and never panics, because a panic in a library ends the adopter's process. The exception is a `const fn` or an associated `const` that checks the arguments of a constant, such as `Document::new` or the default limit of `Page<N>`, which panics on a bad argument, because a panic while the compiler evaluates a `const` is a compile error. A second exception is a clap getter that panics only on a malformed command, such as `Command::get_arg_conflicts_with` on a conflict with an unknown id, because clap's debug build rejects that command when it is built and clap's own parser panics on it in a release build; the call carries a comment that says so. Gate: clippy's `unwrap_used`, `expect_used`, `panic`, `todo` and `unimplemented`, which `clippy.toml` allows in tests, and review for `assert!` in a `const fn` or an associated `const`.
- **RUST-6.** A module with children is `foo.rs` beside a `foo/` directory, never `foo/mod.rs` (ADR-0014). Gate: clippy's `mod_module_files`.
- **RUST-7.** Unit tests live in `foo/tests.rs`, declared in `foo.rs` with `#[cfg(test)] mod tests;`, and each test name is a sentence (ADR-0014). Gate: review.
- **RUST-8.** A `.rs` file has at most 600 lines (ADR-0010). Gate: `cargo xtask check` counts each file's lines and fails, naming every file over 600; split such a file into modules.
- **RUST-9.** `rust-toolchain.toml` pins the stable toolchain and only a pull request of its own moves it (ADR-0009). The MSRV is the workspace `rust-version`, 1.89 (ADR-0003). Gate: review, and `cargo +1.89.0 check --workspace --all-targets --all-features` for the MSRV, which compiles the code behind every feature.
- **RUST-10.** Code that deliberately does less than a maintained crate or a fuller design would says so in a comment at that spot: what it handles, what it misses, and what replaces it once it needs more, so a reader does not copy the shortcut as a convention. The comment is required where copying the shortcut would be costly, such as a hand-written argument or Markdown parser where a crate is the norm, and is unnecessary for a local choice, such as an `if` chain that could be a `match`. Gate: review.
- **RUST-11.** Every property test runs with one fixed seed and without proptest's regression files, and a fix for a failing case adds a unit test that holds the failing input (ADR-0006). The `[env]` table in `.cargo/config.toml` sets `PROPTEST_RNG_SEED` and `PROPTEST_DISABLE_FAILURE_PERSISTENCE`, and `cargo test` and `cargo nextest` pass both to every test. Gate: `.cargo/config.toml`, which review guards.

## Tests

- **TEST-1.** A test that a command line is refused, in crumbkit or in an example tool, also runs a twin: a command line that differs from the refused one by one word added, removed or replaced, and that the tool accepts (ADR-0005). A test that runs the built binary uses crumbkit-test's `check_twin`, and a test inside crumbkit parses the twin with the same parser. The twin shows that the changed word causes the refusal, so the test cannot pass because the command fails for another reason. Gate: `check_twins` in shelf's and reading's tests, which fails on a declared code without a twin, a reason or an opt-out, and on a twin whose admitted line asks for help or the version, runs another command, or runs no command when the refused line runs none, and review for a refusal with one of crumbkit's codes and for the refusals inside crumbkit.

## Output

- **OUTPUT-1.** No result, failure or note that crumbkit or an example tool prints depends on whether a stream is a terminal or on agent detection. The exceptions are help colour, progress, and the questions of pickers and `Output::confirm` (ADR-0049). Gate: shelf's `tests/terminal.rs` on macOS and Linux, which compares each example's bytes at a pseudo-terminal with its golden file, and review.
- **OUTPUT-2.** A failure code's area is a stable noun from the tool's domain, such as `books`, and never names a module or a verb (ADR-0001). Moving code or renaming a command therefore never changes a code. Gate: review.
- **OUTPUT-3.** A listing that mixes healthy entries with degraded ones lists the degraded ones first. A degraded entry is a row whose problem field, which `Row::PROBLEM` names, holds a value, and the run then exits with 1 (ADR-0050). With this order, a limit on the number of entries shown never hides a problem behind healthy entries. Gate: review.

## Documentation

- **DOCS-1.** An `AGENTS.md` has at most 200 words and holds only what no tool or other document tells the agent (ADR-0010). Gate: `cargo xtask check` counts whitespace-separated words and fails, naming every file over 200.
- **DOCS-2.** The Markdown files directly inside one directory of the `docs/` tree total at most 5,000 whitespace-separated words, counting code blocks and tables (ADR-0010). Gate: `cargo xtask check docs` counts each directory on its own and fails, naming every directory over 5,000.
- **DOCS-3.** Every Markdown file under `docs/decisions/` is a decision record whose first line is `# ADR-NNNN. Title`, numbers are unique across the whole tree, code and docs cite a record as `ADR-NNNN`, each directory's `README.md` links to every record in it, and no file outside `docs/decisions/` cites a record whose Status is `superseded by` (ADR-0017). Gate: `cargo xtask check docs` fails on a missing title, a reused number, a citation of a number that no record uses, a citation of a superseded record, a record its node does not list, or a node link to a missing file.
- **DOCS-4.** rustdoc builds without warnings, both in the workspace build and in crumbkit's default build, because a broken link in the API reference leads to no page, and a link to an item behind a feature breaks only in a build without that feature. Gate: `RUSTDOCFLAGS="-D warnings" cargo doc --workspace --no-deps` and the same with `-p crumbkit` in the `lint` job.
- **DOCS-5.** A `README.md` outside `docs/` has at most 650 words, counted as whitespace-separated words over the whole file, including its example and link definitions. One entry in a `CHANGELOG.md`, which is a line starting with `- ` and its indented continuation lines, has at most 40 words (ADR-0013). Gate: `cargo xtask check` fails on a README or an entry over its limit, naming the README or the changelog line where the entry starts, the measured count and the limit.
- **DOCS-6.** A decision record that has a `- Date:` line at the merge base with `main` is frozen: the branch may change only its `- Status:` line and, in a node record, its `## Children` section (ADR-0017). Records are matched by number, so a record may move. Gate: `cargo xtask check` and `cargo xtask check docs` compare each record with its text at `git merge-base HEAD origin/main` and fail, naming each record that the branch edits or removes. A changed decision gets a new record instead.
- **DOCS-7.** When a branch adds or changes an entry under `## [Unreleased]` in a `CHANGELOG.md`, one of its commit messages ends with a trailer that says the docs were swept or records an obligation to sweep them (ADR-0013). The forms are `Docs-Owed: <id>; from: <old behaviour>; to: <new behaviour>; docs: <path>[, <path>...]` and `Docs-Swept: <id>[, <id>...]`, where `<id>` is a kebab-case slug such as `json-layout` and each path names a page or source file. Gate: `cargo xtask check` reads the trailers in the last paragraph of each commit message after the merge base, fails on a trailer that does not parse, and fails when a changelog gained an entry and no commit has a valid trailer. A branch that only removes entries, as a release does, needs none.

- **DOCS-8.** A new decision record whose `Supersedes` line names a record dated less than 7 days before it has a `- Missed:` line that says what the earlier record missed (ADR-0074). The 7 days count calendar days between the two `Date` lines. Gate: `cargo xtask check` and `cargo xtask check docs` fail, naming the new record and the record it amends, when a record that is not at the merge base with `main` amends such a record and has no `- Missed:` line with text.

## CI

- **CI-1.** Every workflow starts with `permissions: {}`, each job grants only the permissions it needs, and every action is pinned to a full commit SHA with a comment naming its version (ADR-0011). Gate: zizmor, which the `lint` job runs on the whole repository, covering the workflows and `.github/dependabot.yml`, and which fails on a workflow without `permissions: {}`, on broad permissions, and on an action pinned by a tag or branch.
- **CI-2.** Every dependency uses a licence and a source that `deny.toml` allows, and every declared dependency is used (ADR-0012). Gate: `cargo deny check bans licenses sources` and `cargo shear` in the `lint` job.
- **CI-3.** The median pull-request run of `ci.yml` takes at most 3 minutes of wall time (ADR-0011). The median covers the last 20 successful pull-request runs, and a run's wall time is the time from its start to its last update. Gate: `cargo xtask ci-time` in the nightly job of `scheduled.yml`, which fails above 180 seconds and when there are no runs to measure; ADR-0011 says where the failure is reported.
- **CI-4.** The workspace builds without warnings and its tests pass on Windows, crumbkit's tier-2 platform, on the newest commit of `main` (ADR-0003, ADR-0011). Gate: the `windows` job of `scheduled.yml`, which runs clippy, the tests and the doctests on `windows-latest` each night that `main` changed since it last passed; ADR-0011 says where the failure is reported, and no release waits for it.

## Performance

- **PERF-1.** Each benchmark in `benches/` stays within its limits on Callgrind's instruction count and DHAT's count of allocated blocks, and each limit is a measured count plus 10 percent, rounded up (ADR-0008). Gate: `cargo bench -p crumbkit-benches` in the `bench` job of `scheduled.yml`, which gungraun fails when a count goes over its limit; ADR-0011 says when the job skips it and where the failure is reported.
- **PERF-2.** The median wall time of a whole run of the release build of shelf, for `books list` and for `commands list --all --json --full`, stays within a budget of 10 ms and fails above 30 ms (ADR-0008). Gate: `cargo xtask run-time` in the `bench` job of `scheduled.yml`, which prints a warning above 10 ms and fails above 30 ms and when there are no runs to measure.

# Standards

Each rule states what crumbkit's own code does, why, and the gate that enforces
it: a lint, an xtask check, or review where no tool reaches. The decision
records in `docs/decisions/` explain the choices behind the rules.

## Rust

- **RUST-1.** Code builds without warnings, because a warning left in the build hides the next one. Gate: `CARGO_BUILD_WARNINGS=deny cargo clippy --workspace --all-targets`, and the same with `-p crumbkit --all-targets` alone, with `--features miette` and with `--features tracing` for crumbkit's default build, its `miette` code and its spans without the usage log. The workspace run covers crumbkit's `miette`, `usage-log` and `tracing` code together, because shelf turns all three features on. The lints are in the root `Cargo.toml`, and every package inherits them through `[lints] workspace = true`.
- **RUST-2.** Code contains no `unsafe`, because crumbkit needs none and forbidding it rules out memory-safety bugs in crumbkit's own code. Gate: rustc's `unsafe_code` at `forbid`.
- **RUST-3.** Code suppresses a lint only with `#[expect(lint, reason = "...")]`, because the reason records why, and `#[expect]` warns when the lint stops firing. Gate: clippy's `allow_attributes` and `allow_attributes_without_reason`.
- **RUST-4.** Environment, process, standard stream and file-write calls happen only in the module that owns each effect, which suppresses the lint with `#[expect]`; other code takes a writer or a value, so its tests run in memory. In the crumbkit crate, `Sink` owns standard output and standard error, the `usage` module owns the usage log's environment reads, files and signal thread (ADR-0029), and the one exception is `parse`, which lets clap's `Error::print` write help and the version to a terminal so that they keep clap's colours (ADR-0021). Gate: clippy's `disallowed_methods` with the list in `clippy.toml`, and `print_stdout`, `print_stderr` and `dbg_macro`.
- **RUST-5.** Code outside tests returns errors and never panics, because a panic in a library ends the adopter's process. The exception is a `const fn` or an associated `const` that checks the arguments of a constant, such as `Document::new` or the default limit of `Page<N>`, which panics on a bad argument, because a panic while the compiler evaluates a `const` is a compile error. Gate: clippy's `unwrap_used`, `expect_used`, `panic`, `todo` and `unimplemented`, which `clippy.toml` allows in tests, and review for `assert!` in a `const fn` or an associated `const`.
- **RUST-6.** A module with children is `foo.rs` beside a `foo/` directory, never `foo/mod.rs`, so each file name says which module it holds. Gate: clippy's `mod_module_files`.
- **RUST-7.** Unit tests live in `foo/tests.rs`, declared in `foo.rs` with `#[cfg(test)] mod tests;`, and each test name is a sentence, so code and tests read separately. Gate: review.
- **RUST-8.** A `.rs` file has at most 600 lines, so a person or an agent can read it whole. Gate: `cargo xtask check` counts each file's lines and fails, naming every file over 600; split such a file into modules.
- **RUST-9.** `rust-toolchain.toml` pins the stable toolchain and only a pull request of its own moves it, so a new clippy release never fails an unrelated change. The MSRV is the workspace `rust-version`, 1.89. Gate: review, and `cargo +1.89.0 check --workspace --all-targets --all-features` for the MSRV, which compiles the code behind every feature.
- **RUST-10.** Code that deliberately does less than a maintained crate or a fuller design would says so in a comment at that spot: what it handles, what it misses, and what replaces it once it needs more, so a reader does not copy the shortcut as a convention. The comment is required where copying the shortcut would be costly, such as a hand-written argument or Markdown parser where a crate is the norm, and is unnecessary for a local choice, such as an `if` chain that could be a `match`. Gate: review.
- **RUST-11.** Every property test runs with one fixed seed and without proptest's regression files, so a CI run generates the same cases on every machine and a fix adds a unit test that holds the failing input (ADR-0006). The `[env]` table in `.cargo/config.toml` sets `PROPTEST_RNG_SEED` and `PROPTEST_DISABLE_FAILURE_PERSISTENCE`, and `cargo test` and `cargo nextest` pass both to every test. Gate: `.cargo/config.toml`, which review guards.

## Documentation

- **DOCS-1.** An `AGENTS.md` has at most 200 words, because an agent reads it at the start of every session, and it holds only what no tool or other document tells the agent. Gate: `cargo xtask check` counts whitespace-separated words and fails, naming every file over 200.
- **DOCS-2.** The Markdown files directly inside one directory of the `docs/` tree total at most 5,000 words, counting code blocks and tables, so each directory can be read in one sitting. Gate: `cargo xtask check docs` counts each directory on its own and fails, naming every directory over 5,000.
- **DOCS-3.** Every Markdown file under `docs/decisions/` is a decision record whose first line is `# ADR-NNNN. Title`, numbers are unique across the whole tree, and code and docs cite a record as `ADR-NNNN`, and each directory's `README.md` links to every record in it, so one search finds every reference to a decision and every record can be reached from the root. Gate: `cargo xtask check docs` fails on a missing title, a reused number, a citation of a number that no record uses, a record its node does not list, or a node link to a missing file.

## CI

- **CI-1.** Every workflow starts with `permissions: {}`, each job grants only the permissions it needs, and every action is pinned to a full commit SHA with a comment naming its version, because a broad token or a movable tag lets a compromised action change the repository or run code that nobody reviewed. Gate: zizmor, which the `lint` job runs on the whole repository, covering the workflows and `.github/dependabot.yml`, and which fails on a workflow without `permissions: {}`, on broad permissions, and on an action pinned by a tag or branch.
- **CI-2.** Every dependency uses a licence and a source that `deny.toml` allows, and every declared dependency is used, because an unexpected licence binds adopters, an unknown source can serve code that nobody reviewed, and an unused dependency adds build time for nothing. Gate: `cargo deny check bans licenses sources` and `cargo shear` in the `lint` job.
- **CI-3.** The median pull-request run of `ci.yml` takes at most 5 minutes of wall time, because a slow pull-request run delays every change and bills more minutes. The median covers the last 20 successful pull-request runs, and a run's wall time is the time from its start to its last update. Gate: `cargo xtask ci-time` in the nightly job of `scheduled.yml`, which fails above 300 seconds and when there are no runs to measure; the failure is reported on the "Scheduled CI failed" issue.
